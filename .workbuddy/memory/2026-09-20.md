## 23:20 全量自检偶发变红 → 挖出并修掉**两个真缺陷**（都已证明）

跑 `reproduce_check` 出现一次「前端布局验收失败」，**但产物里没有任何 `[!! ]` 行**
（只有"见 tools/ui_check.py 输出"）。按用户规矩不许以"偶发"收场，逐层挖到底：

### 缺陷一：前端取数"一个接口失败拖死整组"（`web/app.js`）

`refresh()` 原本 `Promise.all([overview, session-compare, data-status])` ——
**任意一个瞬时失败 → 整组 reject → DATA 三个字段全 null → renderAll() 什么都不画
→ 骨架屏永远留着**；而真浏览器验收的等待条件正是"页面没有 `.sk`" → 浏览器超时
→ 报"浏览器没跑出结果"。**接口是偶发的，表现是页面卡死。**

修法：① `fetchOne()` 逐个取、谁到了渲染谁；② 有缺失点亮错误灯 + **最多补 3 次**（3s 一次）；
③ 新增 `sweepSkeletons()`：**25 秒后把残留骨架换成"暂时取不到数据"**（从根上消灭永久转圈）。

**故障注入证明**（临时实例把 `/api/session-compare` 改成恒定抛错，用自检相同的等待条件跑）：
`sk_count=0`、`fallback_count=1`、**`rows_pairs=10`（关键：一张表挂了另两张照常渲染）**、
`rows_assess=20`、`rows_opp=2`、`live_dot=dot err`。

### 缺陷二：验收脚本自己把失败原因吞了

`reproduce_check` 提取原因只匹配 `"[!! ]"`，而 `ui_check` **首次截图失败**打的是 `[FAIL]`
→ 真正原因被过滤，汇总只剩"见 tools/ui_check.py 输出"。**验收脚本吞原因，本身就是缺陷。**
修法：① 原因提取同时匹配 `[FAIL]`；② `ui_check` 首次截图**失败重试一次**，仍失败就明说
"这不是布局问题，是本机浏览器/负载问题"，把"偶发"与"真回归"分开。
