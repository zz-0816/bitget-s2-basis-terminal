# Basis Terminal · rToken 现货 × 美股永续 跨场所价差

> **Bitget AI Base Camp Hackathon S2 · 赛道一 Alpha Factory · 子主题①「套利」**
> 提交截止：2026-09-21（UTC+8）

---

## 一句话

Bitget 上同一个标的（如 TSLA）同时存在于**两个场所**：rToken 现货 `RTSLAUSDT` 与美股永续 `TSLAUSDT`。
休市时段两者之间稳定存在 **−10 ~ −29 bp 的基差**，而现货点差高达 **3 ~ 32 bp**、永续点差仅 **0.13 ~ 0.92 bp**。
本项目量化这个价差，并把它做成可回测的策略。

## 为什么这不是"折溢价回归"

公开讨论 rToken 时几乎都围绕"折溢价回归"。**该假设已被实测否证**：rToken 与原生股的收盘价平均绝对偏差仅 **0.013%–0.036%**，不存在系统性平台溢价（详见 `docs/03-环境核查记录.md`）。

我们转向的是一个**没有公开攻略讲过**的角度：**同一标的在两个场所之间的价差**。

## 三个物理量（全部实测，非假设）

| 物理量 | 实测值 | 角色 |
|---|---|---|
| **现货点差** | 3.31 – 45.63 bp（中位 ~13 bp） | **成本**，也是 maker 的收益来源 |
| **永续点差** | 0.13 – 0.92 bp | **对冲成本**，几乎可忽略 |
| **跨场所基差** | −10.90 ~ −29.36 bp（全部为负） | **收益来源** |
| 基差均值回归 | AR(1) ρ = 0.533，**半衰期 ≈ 6 分钟** | 决定持仓周期 |

### 交易结构

```
腿 1  做多  rToken 现货    bid 侧挂单（maker）→ 赚点差，不付点差
腿 2  做空  美股永续        即时对冲       → 付 6 bp taker，换方向中性
收益  点差 + 基差收敛
风险  逆向选择 + 点差在开盘瞬间塌缩
```

> **本策略是「做市型价差捕获」，不是无风险套利**——散户无法做 mint/redeem。

---

## ⚠️ 两条硬约束（实测发现，必须写在报告里）

1. **永续腿的深度是真正的瓶颈。** 现货 24h 成交量常达永续的 **数百至数万倍**；永续顶部盘口深度中位仅约 **$400**。
   标注「深度不足」的标的，**基差再大也无法承载有意义的下单规模**。
2. **永续 1H K 线仅回溯约 41 天。** 日线可回到 2025-08-18（389 天，满足 ≥60 天要求），
   但高粒度序列较短。策略按**做市策略**定性，依手册条款以**高/低波动环境连续记录**替代 60/30 天区间回测。

## 快速开始

```powershell
# 1) 双场所盘口采样（常驻；这是策略能否成立的关键数据）
python spread_sampler.py --loop --interval 60

# 2) 历史 K 线回补（日线 + 小时线 + 分钟线）
python backfill_history.py --matrix

# 3) 启动监控台
python server\app.py --port 8787
#    打开 http://127.0.0.1:8787
```

**无需任何 API Key**——全部使用 Bitget 公开行情端点。

### 环境要求

- Python **3.10+**（仅用标准库；`zoneinfo` 用于美东时段判定）
- 无需 pandas / numpy（规避 Python 3.14rc 预发布版的 wheel 缺失风险）
- 出网：直连 `api.bitget.com`。**`curl.exe` 在 Windows 上存在 schannel 凭据 bug，请勿使用**，本仓库一律用 Python `urllib`。

## 关键实现细节

- **时段判定用 `zoneinfo` 的 `America/New_York`**，禁止硬编码 ±4/±5——夏令时切换会让休市窗口错位 1 小时。
- **粒度写法两场所不同**：现货 `1min`/`1day`/`1h`，永续 `1m`/`1D`/`1H`。写错报 400。
- **现货 1min 有缺口**（零成交分钟不上线，实测缺口率 73.9%），永续连续。
  两场所对齐**必须取时间戳交集，禁止前向填充**（会制造前视偏差）。
- 采样器内置**单实例锁**，防止重复写同一 CSV。
