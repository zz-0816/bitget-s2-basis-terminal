## 一句话

Bitget 上同一个标的（如 TSLA）同时存在于**两个场所**：rToken 现货 `RTSLAUSDT` 与美股永续 `TSLAUSDT`。
休市时段两者之间稳定存在 **+10 ~ +29 bp 的基差**，而现货点差高达 **3 ~ 32 bp**、永续点差仅 **0.13 ~ 0.92 bp**。
本项目量化这个价差，并把它做成可回测的策略。

> **基差符号约定**：`basis_bp = (永续/现货 − 1) × 10000`，**正 = 永续升水**（现货便宜）。
> 因此交易方向恒为「**多现货 / 空永续**」。换算：本约定 = −(现货/永续 − 1)，与旧写法互为相反数。

## 为什么这不是"折溢价回归"

公开讨论 rToken 时几乎都围绕"折溢价回归"。**该假设已被实测否证**：rToken 与原生股的收盘价平均绝对偏差仅 **0.013%–0.036%**，不存在系统性平台溢价（详见 `docs/03-环境核查记录.md`）。

我们转向的是一个**没有公开攻略讲过**的角度：**同一标的在两个场所之间的价差**。

## 三个物理量（全部实测，非假设）

| 物理量 | 实测值 | 角色 |
|---|---|---|
| **现货点差** | 3.31 – 45.63 bp（中位 ~13 bp） | **成本**，也是 maker 的收益来源 |
| **永续点差** | 0.13 – 0.92 bp | **对冲成本**，几乎可忽略 |
| **跨场所基差** | **+7 ~ +29 bp（全为正 = 永续升水）** | **收益来源** |
| 基差均值回归 | **分时段**：周末 ρ=0.8799 / 半衰期 ≈27 分钟；工作日 ρ≈0.67 / ≈9 分钟 | 决定持仓周期 |

> **基差分时段中位（`(永续/现货−1)`，正 = 永续升水）**
>
> | 面板 | 时段 | 中位基差 |
> |---|---|---|
> | 1h（10 配对 / 58 天） | 休市 | **+12.49 bp** |
> | | 盘前 | +11.21 bp |
> | | 盘中 | **+10.35 bp** |
> | | 盘后 | +9.77 bp |
> | 1day（213 配对） | 周末 | **+8.12 bp** |
> | | 工作日 | **+7.08 bp** |
>
> ⚠️ 日线粒度的 `closed` 实为"周末那一根"，**时段结论只能用 1h 面板**（日线无法区分盘中/夜间）。

> **关于早期那个"ρ=0.533 / 半衰期 6 分钟"**：那是一次实时探针用**约 200 根 5min（仅 ~17 小时）**算的，样本太短。
> 14 天全样本复算后**整体 ρ 中位 0.8567**，但**整体值不可比**（混合了周末与工作日两种市场结构）。
> 现改为**分时段**给出，落盘数据见 `data/derived/basis_5m_*.csv`，复跑 `tools/export_basis_series.py`。

### 交易结构

```
腿 1  做多  rToken 现货    bid 侧挂单（maker）→ 赚点差，不付点差
腿 2  做空  美股永续        即时对冲       → 付 6 bp taker，换方向中性
收益  点差 + 基差收敛
风险  逆向选择 + 点差在开盘瞬间塌缩
```

> **本策略是「做市型价差捕获」，不是无风险套利**——散户无法做 mint/redeem。

## ⚠️ 三条硬约束（实测发现，必须写在报告里）

1. **永续腿深度极薄，且高度时变。** 按 `min(bid, ask)` 口径，`data/universe.csv` 快照（09-12 22:02）中位仅 **$50**，**213 个配对里有 173 个低于 $1,000**（分布 $2 ~ $298k）。
   ⚠️ **但"哪条腿是瓶颈"不能一概而论**：同一时刻实测（09-13 01:40）现货腿中位 $419 / 永续腿中位 $477 —— **两者相当**；
   而另一快照下现货腿（$459）远深于永续腿（$49）。**深度随时段剧烈变化，结论必须按快照时间标注。**
   → 因此报告应给出**容量曲线（随时间的深度分位数）**，而不是单一数字；下单量必须做**深度感知**。
2. **成交量层面永续腿明显更小。** 现货 24h 成交量常达永续的**数百至数万倍**（如 SPY 41,173×）；
   但点差维度上永续反而更窄（0.13–0.92 bp）——**"薄"体现在量，不体现在报价宽度**。
3. **高粒度历史受限。** **永续 1H 仅回溯 58 天**（2026-07-16 起，1h 面板实测）；日线可回到 2025-08-18（389 天，满足 ≥60 天要求）。
   策略按**做市策略**定性，依手册条款以**高/低波动环境连续记录**替代 60/30 天区间回测。

## 快速开始

### 第 0 步（强烈建议）：先跑自检

```powershell
python tools\reproduce_check.py
```

它会用**约 60 秒**验证四件事：环境是否合规、报告结论依赖的快照是否随仓库分发、
每个脚本能否导入并 `--help`、报告里的核心数字能否从已提交快照重算出来。
**退出码 0 = 通过**。这一步会替你省掉"到底该信哪份数据"的猜测。

> 这个自检本身是有来历的：第一次在**全新克隆**里跑，就抓出一个真实缺陷 ——
> `build_panel.py` 在缺少 `data/raw/` 时会解析出 0 行却照样写文件，
> 把已提交的 2.4 MB 面板覆盖成空文件、退出码还是 0。
> 现在它在 0 行时会**拒绝写入**并告诉你正确的前置步骤（见下面的"两种复现方式"）。

### 两种复现方式（先想清楚你要哪一种）

| 你想要 | 怎么做 | 能拿到什么 |
|---|---|---|
| **A. 复现报告结论**（推荐，评委/队友） | 什么都不用装，直接读仓库里已提交的快照：`data/panel/*.csv`、`data/derived/*.csv`、`data/samples/*.csv.gz` | 报告里每个数字的来源文件；`tools\reproduce_check.py` 会替你核对 |
| **B. 从零重建数据** | 联网跑 `python backfill_history.py --matrix` → `python build_panel.py --gran 1h` | 重新抓的 K 线面板。**注意 `1min` 只能回溯约 13.9 天**，重建出来的样本会比报告用的短 |

> ⚠️ `data/raw/`（历史 K 线，400 MB+）**不在仓库里**，这是刻意的体积取舍。
> 所以方式 B 必须**先联网抓数**；直接 `python build_panel.py` 会（按设计）拒绝写入并提示你。

python server\app.py --port 8787

### 要采集新数据时

```powershell
# 四个采样器由守护进程统一起停（自动接管已在运行的实例，不会重复启动）
powershell -ExecutionPolicy Bypass -File scripts\sampler_supervisor.ps1
python tools\check_samplers.py     # 退出码 0 = 健康（实例数/节奏/重复 trade_id）
```

采样器：`spread_sampler.py`（10 配对最优一档，60s）、`sampler_universe.py`（213 配对轮转，30s）、
`orderbook_sampler.py`（10 配对 × 5 档 × 2 侧，30s）、`trades_sampler.py`（逐笔成交，60s）。
**这四类数据交易所都不提供历史接口，漏掉就永久拿不回来** —— 详见 `docs/DATA_DICT.md`。

**无需任何 API Key**——全部使用 Bitget 公开行情端点。

### 环境要求

- Python **3.10+**（仅用标准库；`zoneinfo` 用于美东时段判定）
- 无需 pandas / numpy（规避 Python 3.14rc 预发布版的 wheel 缺失风险）
- 出网：直连 `api.bitget.com`。**`curl.exe` 在 Windows 上存在 schannel 凭据 bug，请勿使用**，本仓库一律用 Python `urllib`。
- 实测全新克隆：**约 35 秒 / 326 MB**（其中 `.git` 264 MB，含早期误提交的 `data/raw` 历史；工作区内容约 61 MB）

### 常见问题

| 现象 | 原因与处置 |
|---|---|
| `build_panel.py` 拒绝写入、退出码 3 | **预期行为**：缺 `data/raw/`。先 `backfill_history.py --matrix`，或改用已提交的快照 |
| 控制台中文/符号乱码或脚本中断 | Windows 控制台是 GBK；已由 `common/console.py` 统一兜底。若仍异常，跑 `python common\console.py` 自检 |
| `--gran 1h,1D` 报错 | PowerShell 会按逗号拆参数，**必须加引号**：`--gran "1h,1D"` |
| `/api/timeline` 返回 `[]` | 说明既没有原始 CSV 也没有 gz 归档；跑 `python tools\audit_samples.py` 查采样真实性 |

## 关键实现细节

- **时段判定用 `zoneinfo` 的 `America/New_York`**，禁止硬编码 ±4/±5——夏令时切换会让休市窗口错位 1 小时。
- **粒度写法两场所不同**：现货 `1min`/`1day`/`1h`，永续 `1m`/`1D`/`1H`。写错报 400。
- **现货 1min 有缺口**（零成交分钟不上线，实测缺口率 73.9%），永续连续。
  两场所对齐**必须取时间戳交集，禁止前向填充**（会制造前视偏差）。
- 采样器内置**单实例锁**，防止重复写同一 CSV。
