# 乙侧数据说明（`data/b-side/`）

> **一句话**：这是**另一台机器（乙侧）**在 2026-09-11 ~ 09-13 采集/抓取的原始数据。
> Bitget 不提供历史 bid/ask，`spread/` 里的是**不可回补**的样本；`raw/` 可直接复现乙侧的全部检验结论。
> 时点：**2026-09-13 00:35 CST**（`spread/` 是**时点快照**，乙侧本机仍在继续采集）

## 二、`spread/` —— 乙侧机器的逐分钟盘口（不可回补）

| 文件 | 行数 | 轮数 | 时段（UTC） | 说明 |
|---|---|---|---|---|
| `2026-09-12.csv` | 592 | 30 | 15:14:12 → 15:59:46 | 轮间隔中位 **60.0 s**（另有 2 个 <50s、1 个 1045s 停顿 —— 乙侧切换采样实例所致） |
| `2026-09-13.csv` | 700 | 35 | 16:00:46 → 16:34:46 | 轮间隔 **恒 60.0 s**，**仍在增长** |

- **每轮 20 行** = 10 个配对 × 2 个场所（spot / perp）
- **配对**：`TSLA NVDA AAPL META GOOGL SPY QQQ SOXL HOOD MRVL`
- **列**与你 `spread_sampler.py` 的输出**逐字相同**（`ts_utc, ts_ms, date_cn, symbol, venue, base, bid, ask, mid, spread_bp, bid_sz, ask_sz, last, usdt_vol_24h`）→ 可直接 `csv` 拼接
- ⚠️ **`base` 已规范化**：乙侧这份采样器从 `d11d19f` 复制，带着 `rstrip('USDT')` 的 bug（`RHOODUSDT` → `HOO`）。
  本目录的 CSV 已用 `symbol` 重建 `base`（共修正 129 行）；**你那边 `data/spread/2026-09-12.csv` 还有 644 行待清洗**，工具见 `tools/b_side_normalize_base.py`

### 合并到你的序列时，注意两点

1. **保留来源标记**：不同机器轮次密度不同，直接拼接会让 `15:14–15:39 UTC` 这段的轮次密度翻倍。
   时间加权统计前须**按轮次去重**（与你 `08` §三.A 处理"两个实例并行"时段的原则相同）。
2. **来源是另一台机器**（你 `08` Q2 的建议）：本目录即按此标注，**不会与你的序列混为一谈**。

### 一致性已验证

两台机器**同时段同标的**的中间价中位差 **0.00 bp**、均值 0.20 bp、最大 5.92 bp（492 组对照），
差异集中在流动性最差的永续腿 —— 详见 `docs/b-side/双机交叉验证-20260912.md`，复现：`python tools/b_side_crosscheck.py --repo .`

## 四、复现入口一览

```bash
# 双机一致性对照（读 data/spread/ 与 data/b-side/spread/）
python tools/b_side_crosscheck.py --repo .

# base 清洗（先干跑）
python tools/b_side_normalize_base.py --repo . --dry-run

# 折溢价 / 同步性 / fade 检验（读 data/b-side/raw/）
python tools/b_side_checks.py

# 对面板与盘口做独立复算（读 data/）
python tools/b_side_verify_panel.py
```

> 全部脚本**仅用标准库**，路径自定位（`__file__` 的上一级 = 仓库根），换位置可直接跑。
