> **一句话**：这是**另一台机器（乙侧）**采集的原始数据。
> Bitget 不提供历史 bid/ask，`spread/` 里的是**不可回补**的样本；`raw/` 可直接复现乙侧的全部检验结论。
> 时点：**2026-09-15 08:51 CST**（`spread/` 是**时点快照**，乙侧本机仍在继续采集）

### 2026-09-15.csv 的覆盖与缺口（如实标注）

- 时段：**09-15 00:00:01 → 09-15 00:51:39**，共 **10 轮 / 200 行**
- **缺口 1 处，合计 43.6 分钟**：
  - `09-15 00:06:01 → 09-15 00:49:39`（43.6 分钟）
- **每轮不足 20 行：0 轮**（单腿被远端断开，脚本跳过不补；不应据此判数据损坏）
- **窗口起点缺口**：平台所内撮合窗口（`in_house`）为**周六 08:00（北京）**起，
  乙侧实例 **09-12 23:14 才启动** → 09-12 08:00–23:14 这 **15.2 小时为空，不可回补**。
- **每小时轮数**（用于判"是否有第二个写入者"）：00=10

### 规格

- **每轮 20 行** = 10 个配对 × 2 个场所（spot / perp）
- **配对**：`TSLA NVDA AAPL META GOOGL SPY QQQ SOXL HOOD MRVL`
- **列**与甲侧 `spread_sampler.py` 输出**逐字相同**
  （`ts_utc, ts_ms, date_cn, symbol, venue, base, bid, ask, mid, spread_bp, bid_sz, ask_sz, last, usdt_vol_24h`）→ 可直接拼接
- **`base` 已规范化**：乙侧采样器从 `d11d19f` 复制，带着 `rstrip('USDT')` 的 bug
  （`RHOODUSDT` → `HOO`；**凡以 T/S/D/U 结尾的代码都会被多剥一位**）。
  本目录 CSV 已用 `symbol` + `venue` 重建 `base`（本次共修正 **4110** 行），清洗后与既有版本逐行零差异。
  甲侧 `data/spread/*.csv` 如有同类问题，用 `tools/b_side_normalize_base.py` 处理。

### 合并到甲侧序列时注意

1. **保留来源标记**：不同机器轮次密度不同，直接拼接会让重叠时段的轮次密度翻倍。
   时间加权统计前须**按轮次去重**。
2. **来源是另一台机器**：本目录即按此标注，不与甲侧序列混为一谈。
3. **缺口不可回补**：下游按 `ts_ms` 直接跳过，不要插值。

## 三、复现入口

```bash
python tools/b_side_crosscheck.py --repo .        # 双机一致性对照（09-12 一次性）
python tools/b_side_normalize_base.py --repo . --dry-run   # base 清洗（先干跑）
python tools/b_side_checks.py                     # 折溢价/同步性/fade 检验
python tools/b_side_verify_panel.py               # 面板与盘口独立复算
```

> 全部脚本**仅用标准库**，路径自定位，换位置可直接跑。
