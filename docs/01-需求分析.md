## 4. 策略机制：把价差分三类

> 这是本项目的**理论核心**，也是"Alpha 来源说明"最值钱的一段。

### 4.1 价格分解

```
rToken 价格 P  =  P_official_close × (1 + info + resid)

  info   = 市场对「下一个开盘」的理性预期      → 真实信息，77–95% 正确
  resid  = 由休市期局部供需造成的残余偏离      → 唯一可套利的对象
  点差    = (ask − bid) / mid                 → 交易成本，也是 maker 的收益来源
```

**观测到的总偏离 `dev = info + resid`，其中只有 `resid` 可交易。**

### 4.2 如果用 taker 方式（❌ 算术上不成立）

| 项 | 数值 |
|---|---|
| 看到的偏离 `dev` | 假设 +15 bps（有吸引力） |
| 吃单成本（单边半幅点差） | **−5.6 bps**（中位 11.24 的一半） |
| 平仓再付一次 | **−5.6 bps** |
| 手续费（双边） | **−X bps**（待 OQ-1） |
| **净收益** | **≈ +3.8 − X bps** |

→ **在 TSLA（32 bps 点差）上，双边点差成本就是 32 bps**，任何 10–20 bps 级别的偏离都不可能覆盖。**taker 路线直接排除，且这是可写进报告的硬结论。**

### 4.3 如果用 maker 方式（✅ 唯一可行路径）

```
① 在 bid 侧挂限价买单（赚半幅点差，而非付它）
② 被成交后，等待以下任一收敛/平仓条件：
     a) 点差收窄 → 在 ask 侧挂单卖出（赚另一半幅）
     b) 下一开盘价落地 → 收盘
     c) 残余偏离回归 → 提前平仓
③ 收益 = 半幅点差 + 残余回归 − 手续费 − 滑点
```

**核心风险（必须专门检验，R6）**：**逆向选择**。挂单被成交，往往是因为有人知道你不知道的事（休市期出现新闻）。**"赚点差"能否成立，完全取决于"被成交时的信息劣势"是否小于点差收益。**

> 这一步是本项目的**科学诚实性所在**：我们不假设挂单一定赚钱，而是**把逆向选择量化出来**。

### 4.4 四层结构

```
① 分解层   dev = info + resid          （用原生股日线 + rToken 分钟线估计）
② 过滤层   |resid| > 门槛 τ  且  点差 ≤ 上限 σ  且  非财报窗口
              ↓
③ 执行层   maker 挂单（bid 侧）→ 收敛后平仓（ask 侧）
              ↓
④ 评估层   Sharpe / Sortino / MaxDD / 换手 / 样本外衰减 / **逆向选择成本**
```

**门槛 τ 的直觉**：因为赚的是点差+回归，**点差越宽越值得做，点差越窄越不值得**——这与"点差异常宽本身就是风险补偿"的做市理论一致。

## 5. 需求清单

优先级：**P0 = 不做就失去参赛资格或失去核心竞争力**；P1 = 明显加分；P2 = 明确砍掉或仅留说明。

### 5.1 功能性需求

#### F0 · 时段标定（P0）
见 §3。**验收**：`session_label()` 单实现；各时段样本量报告；DST 用 `zoneinfo`。

#### F1 · 价差分解：info 与 resid 分离（P0）
- **描述**：以 `P_official_close`（最近一次**已收盘**的官方收盘）为锚，估出 `info`（下一开盘预期）与 `resid = dev − info`。
- **`info` 的估计方法（三选一，需在 9/14 前定案并写进报告）**：
  1. **朴素**：`info = 0` → `resid = dev`（则策略=折溢价回归，**文档已证明不行**，仅作基线）
  2. **建议主用**：用**已发生的同向后续**构造，即用 t 时点**可得**的信息预测 t+1 开盘（禁止前视）
  3. **稳健**：用原生股盘前/盘后真实成交价作 `info` 的**外生代理**（若 Yahoo 可取盘前数据）
- **验收**：`resid` 序列的自相关与**均值回归半衰期**有量化报告；**必须证明 `resid` 不是纯噪音**（否则 F2 无意义）。

#### F2 · 残余偏离的均值回归检验（P0 · 决定策略生死）
- **描述**：检验 `resid` 在**开盘/点差收窄**时是否显著收敛。
- **验收**：给出回归系数、t 值、半衰期；**分时段**（隔夜/盘前/周末）分别报告。**若周末窗口无显著回归，周末策略直接砍掉。**

#### F3 · 点差采样与点差统计（P0 · 本项目护城河）
- **描述**：**逐分钟**采样 `tickers`（bid/ask/bidSz/askSz），产出分时段、分标的的点差分布（中位/分位/最差）。
- **为什么必须采样而不能靠 K 线**：实测 **1min K 线缺口率 73.9%**（零成交分钟不上线），**点差的真实分布只能靠主动采样**。
- **验收**：`data/spread/` 按日分区、追加写、可续跑；输出 `costs.json` 含悲观/中性/乐观三档。

#### F4 · 成本模型（P0）
- **三项分开返回**（禁止合并成一个数）：`{fee_bp, half_spread_bp, slip_bp}`
- **方向敏感**：**maker 与 taker 的成本不同号**（maker 赚半幅点差）。成本模型必须接受 `liquidity_role ∈ {maker, taker}`。
- **验收**：`python -c` 最小复现；费率取自官方页面（OQ-1），**不沿用转述值**。

#### F5 · 价差闸门（P0）
- **描述**：`|resid| > τ` **且** `点差 ≤ σ_max` 才下单；**taker 模式一律不放行**（除非闸门证明可覆盖）。
- **验收**：回测日志可验证"拦掉数 / 放行数"；放行子集净收益显著高于全体。

#### F6 · maker 挂单成交模型（P0 · 最容易做假的地方）
- **描述**：模拟限价单在 bid 侧的成交与排队。**必须明确列出所用假设，并做敏感性分析。**
- **可选假设（按保守度排序）**：
  - 保守：价格触及 bid **且**该分钟有成交 → 成交（**可能高估成交率**）
  - 中性：触及即成交，但对每笔施加固定逆向选择惩罚
  - 乐观：仅触及即成交（**禁止单独使用，必须与保守档对比**）
- **验收**：**至少两档假设下都跑出结果**；报告写明结论对成交假设的敏感性。

#### F7 · 逆向选择量化（P0 · 本项目最有价值的分析）
- **描述**：统计"挂单成交后 N 分钟/到下一开盘的价格漂移"。**若漂移显著为负，点差收益就是风险补偿而非免费午餐。**
- **验收**：输出 `adverse_selection_bp`（分时段、分标的）；报告结论须回答："赚到的是点差，还是被逆向选择吃掉的点差？"

#### F8 · 回测引擎与报告（P0 · 硬门槛）

- **验收**：见 §6 门禁 G1–G4。

## 附：术语口径统一（防两人理解偏差）

| 词 | 本项目内的**精确**含义 |
|---|---|
| `dev_bp` | `(P_rtoken / P_official_close − 1) × 10000`，**单位 bps** |
| `info` | `dev` 中可归因于"下一开盘合理预期"的部分 → **跟随，不套利** |
| `resid` | `dev − info` → **唯一套利对象，赌其回归** |
| `spread_bp` | `(ask − bid) / mid × 10000`，**全幅** |
| maker / taker | maker **赚**半幅点差；taker **付**半幅点差。**成本符号相反** |
| 逆向选择 | 挂单成交后价格朝不利方向的漂移，**单位 bps，是点差收益的对手项** |
| 衰减比 | `Sharpe_OOS / Sharpe_IS`，红线 **≥0.5** |
| 休市期 | 见 §3 表，**默认不含盘中** |
