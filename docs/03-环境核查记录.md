## 3.1 ✅ 后续突破：网络其实通的，`curl` 才是那个坏掉的环节

**关键发现**：`curl.exe` 报的 `schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)` 是 **Windows schannel 的凭据 bug，不是网络策略问题**。

用 `curl.exe -v` 观察，**代理隧道本身完全成功**：
```
* Establishing HTTP proxy tunnel to api.bitget.com:443
> CONNECT api.bitget.com:443 HTTP/1.1
< HTTP/1.1 200 Connection established     ← 隧道通了
* schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS   ← 之后才失败
```

**改用 Python `urllib` 直连立即成功**（本机 Clash 代理监听 `127.0.0.1:7890`，系统 WinINET 已设 `ProxyEnable=1`）：

```
https://api.bitget.com/api/v2/spot/market/tickers?symbol=RTSLAUSDT
→ {"code":"00000","msg":"success","data":[{"lastPr":"364.38","bidPr":"364.3",
   "askPr":"365.46","bidSz":"41.04","askSz":"68.0859", ...}]}
```

**结论（修正文档铁律）**：

| 文档说法 | 实测结论 |
|---|---|
| "联网一律走 WSL" | ❌ **不需要**。Python 直连可用，WSL 在本环境甚至被沙箱拒绝 |
| "Windows curl 全 000（SSL error 35）" | ⚠️ 方向对但归因错：**是 schannel 凭据问题**，非网络问题 |
| 粒度必须写 `1day`/`1h` | ✅ 仍然正确（`1D` 会报 400171） |
| 翻页必须用 `candles` + `endTime` | ✅ 仍然正确 |

**请你们各自实测并回报**（用 Python，不要用 curl）：
```python
import threading, urllib.request, json
out = {}
def go():
    try:
        out['d'] = urllib.request.urlopen(
            "https://api.bitget.com/api/v2/spot/market/tickers?symbol=RTSLAUSDT",
            timeout=25).read()[:200]
    except Exception as e:
        out['e'] = repr(e)
t = threading.Thread(target=go); t.start(); t.join()
print(out)
```
> **注意**：本沙箱里 `urllib` 必须放进 `threading.Thread` 才通（直接调用报 "can't create new thread"）——这是沙箱特性，你们本机不需要这样写。

## 3.2 ✅ K 线粒度远超文档认知：`1min` 可用（但有缺口）

文档只提到 `1h`。实测 Bitget `candles` 支持更细粒度：

| granularity | 结果 | 返回 5 根的跨度 |
|---|---|---|
| **`1min`** | ✅ **OK** | 117 分钟 |
| `5min` | ✅ OK | 120 分钟 |
| `15min` | ✅ OK | 135 分钟 |
| `1h` | ✅ OK | 300 分钟 |

**⚠️ 但有一个致命细节**：**零成交的分钟不上线**，1min 序列**不连续**。
- 实测：一个 **765 分钟**的窗口里只返回 **200 根**（`limit=200`），**缺口率 73.9%**。
- 时间戳跳跃示例：`08:49 UTC` 之后直接跳到 `10:16 UTC`（中间 87 分钟无数据）。

**对需求的影响（已写入 F1/F3）**：
1. **点差的真实分布无法只靠 K 线重建** → **必须主动轮询 `tickers` 采样**，采样器是必需品而非可选项。
2. 回测中**必须明确声明"零成交分钟"的处理方式**，否则指标口径不可比。

## 3.6 ✅✅ 最重要发现：Bitget 有**美股永续合约**，构成跨场所套利

### 3.6.1 同一标的、两个场所，点差差 100 倍

实测（2026-09-12 20:45 CST，美股休市）：

| 标的 | 场所 | bid | ask | **点差 (bps)** |
|---|---|---|---|---|
| **TSLA** | rToken 现货 `RTSLAUSDT` | 364.30 | 365.46 | **31.79** |
| | **美股永续 `TSLAUSDT`** | 365.87 | 365.88 | **0.27** |
| **NVDA** | rToken 现货 `RNVDAUSDT` | 218.90 | 219.00 | 4.57 |
| | **美股永续 `NVDAUSDT`** | 219.35 | 219.36 | **0.46** |
| **AAPL** | rToken 现货 `RAAPLUSDT` | 332.77 | 332.88 | 3.31 |
| | **美股永续 `AAPLUSDT`** | 333.36 | 333.38 | **0.60** |

**同标的确认**：两者 1D K 线开盘时间戳**完全相同**（`1789142400000`），价格几乎一致（现货 365.18 / 永续 365.45）。

### 3.6.2 基差与合约规格

| 标的 | 现货 mid | 永续 mid | **基差 (bps)** |
|---|---|---|---|
| TSLA | 364.880 | 365.875 | **−27.20** |
| NVDA | 218.950 | 219.355 | **−18.46** |
| AAPL | 332.825 | 333.370 | **−16.35** |

**合约规格实测**：`makerFeeRate=0.0002`（2 bps）/ `takerFeeRate=0.0006`（**6 bps**）/ `maxLever=100` / `minLever=1` / `minTradeNum=0.01` / `sizeMultiplier=0.01` / `fundInterval=8`（8 小时结算）/ 资金费率区间 ±0.005 / 当前 `fundingRate=0`。

**粒度写法（⚠️ 两场所不同，写错报 400）**：现货用 `1min`/`5min`，合约用 `1m`/`5m`；`1H`/`1D` 两边通用。

### 3.6.3 基差均值回归实测（决定策略可行性）

5min 对齐，90 个样本，09-11 20:10 → 09-12 10:30：

- 基差 `mean = −11.01 bp`，`sd = 8.90`，`min = −29.55`，`max = +6.57`，`median = −8.00`
- **AR(1) 自相关 ρ = 0.533 → 半衰期 ≈ 6 分钟**

**⚠️ 一个必须注意的数据陷阱**：1min 粒度下，现货 200 根覆盖 765 分钟、永续 200 根覆盖 200 分钟，**时间戳交集只有 2 个点**。原因是现货 1min **零成交分钟不上线**（缺口率 73.9%）而永续连续。
→ **对齐必须用时间戳交集，且禁止用 `ffill` 前填现货价格**（会直接制造前视偏差，N4）。

### 3.6.4 三点论断

1. **套利机会真实存在**：16–27 bps 稳定基差，双边吃单费 16 bps（现货 10 + 永续 6）→ 可覆盖；**永续支持做空，绕开了"rToken 不能做空"的死结**。
2. **但现货腿必须 maker**：TSLA 现货点差 32 bps，吃单直接吃穿基差 → 策略须定性为**做市 / liquidity provision**（这同时解锁手册的替代性回测条款）。
3. **粒度要求高**：半衰期仅 6 分钟 → 1min 偏粗，需秒级盘口采样。

## 6. 一句话总结

**唯一真正紧急的事：今晚让点差采样器跑起来。**

理由：`01-需求分析.md` C1 显示"最后一个可采样的周末"**只剩 9/13 一天**，而 C2 显示原采样器脚本在本机不存在；同时 §3.3 已实测证明**点差（中位 11.24 bps）比文档假设的毛利（≈10 bps）还大**，而 §3.2 证明**点差的真实分布无法靠 K 线重建**（1min 缺口率 73.9%）。

→ **采样窗口一旦错过，成本模型（本项目最核心的差异化）就只剩估值。** 其余任务都还有 1–2 天缓冲，采样没有。
