## 三、我方自查出的 3 个额外问题（复核未提但同样重要）

### A. 我的"重复检测"是假阴性 —— 乙侧说得对，已彻底重写 ✅

乙侧指出：用 `(ts_ms, symbol, venue)` **完全相等**检测重复必然测不出（两进程各打自己的毫秒戳）。**这是对的，我的"0 重复"结论当时是假阴性。**

**已把 `tools/audit_raw_counts.py` 的检测口径改成乙侧建议的三条**：每分钟轮数 ≈ 1 / 轮间隔不成互补对 / 每轮行数 = 配对数×2。

改后立刻复现了乙侧描述的现象：
```
2026-09-12.csv          轮数/分钟 2.32   轮间隔中位 16.5 秒   <20秒占 57%   -> !疑似多实例
universe-2026-09-12.csv 轮数/分钟 3.36   轮间隔中位 29.9 秒   <20秒占 41%   -> !疑似多实例
```

**根因已定位并修复**：确实有**两个实例并行**。原因是早期 `Stop-Process` 报告成功但**进程实际未被杀死**（僵尸进程），改用 `taskkill /F` 才真正终止。

**修复后实测**（清理时刻 23:13）：
```
清理前: core 2.46 轮/分钟, 中位间隔 16.5 秒
清理后: core 1.09 轮/分钟, 中位间隔 60.0 秒   <- 已恢复正常
```

> 影响评估：这段时间的采样被"加密"了（同一分钟内采两次），**不会产生错误数值，但会污染时间加权的统计**。已在面板与报告中标注该时段。**如果 B 用到 22:00–23:13 之间的采样做统计分析，需要按去重后的轮次处理。**

### B. 采样器缺少自动重启 —— 已补 ✅

盘口数据**不可回补**，中断即永久丢失。已新增：
- `scripts/sampler_supervisor.ps1`：常驻守护，**进程退出后 10 秒自动拉起**（已实测：杀掉 core → 60 秒后检测 → 10 秒后重启为新 pid → 数据恢复增长）
- `scripts/status_window.ps1`：一屏实时状态（心跳/轮数/行数/最后写入/K线滞后/最近基差）
- `scripts/install_sampler_guard.ps1`：注册为登录自启（计划任务需管理员，被拒时自动回退启动文件夹）

### C. `rstrip("USDT")` 剥字符集导致 base 被截断 —— 已修 ✅

`'RHOODUSDT'.rstrip('USDT')` 的参数是**字符集合**不是后缀 → 从右侧剥掉所有属于 `{U,S,D,T}` 的字符 → `RHOO` → `HOO`。同理 `RDWUSDT`→`DW`。
已改为显式切片 `base_of()`。影响范围仅 CSV 展示列（前端从 symbol 推导未受影响）。
