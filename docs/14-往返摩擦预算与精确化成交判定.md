## 1. `docs/13` 的乐观来自哪里（三处系统性偏差）

`docs/13` §3.2 的 `净(中位档) = B_maker − 5.0 − 6.0`，其中

| # | 偏差 | 方向 | 实测修正 |

## 2. 方法：用**逐笔成交**判定挂单成交（不再是推断）

数据：`data/spread/trades-*.csv`（`trades_sampler.py` 采的成交流水，
含 `tradeId` 去重，覆盖 2026-08-22 → 09-14；`--backfill` 已回补 100 页 / 90,001 笔）。

```
成交判定（与 orderbook 快照最近邻对齐，容差 ±20 秒）
  现货腿：我们挂 bid（我们是买家）→ trade.price <= best_bid  才算我们可能成交
  永续腿：我们挂 ask（我们是空头）→ trade.price >= best_ask  才算我们可能成交
逆向选择
  f_dmid(k) = 成交后第 k 个快照的 mid 漂移，**已按方向翻符号：正 = 对我们有利**
```

> ⚠️ **方向是本项目最容易搞错的地方**。早期版本对永续腿用了 `price <= best_bid`
> （即"我们挂买单"），方向完全相反；本文件已用 `--side` 显式区分并在代码里断言。

**为什么比 `maker_fill_model.py`（快照推断法）可信**：

| | 旧版快照推断 | 本版逐笔成交 |
|---|---|---|
| 成交判据 | best_bid 是否下移 → **猜** | 成交价是否打到我们的价位 → **观测事实** |
| 偏差 | 结构性**偏悲观**（必然成交在下跌中） | 无此结构偏差 |
| 逆向选择起点 | 快照边界（模糊） | **成交时刻本身**（精确） |

### 4.1 ⭐⭐ 补丁：漏掉的**资金费率**一项（09-14 追加）

上面的门槛**漏了一项成本**：本策略是「多现货 / **空永续**」，
空头在每个结算点按资金费率收付。永续 8 小时结算一次
（`fundInterval=8`），一个 `in_house` 窗口 48 小时 = **最多 6 次结算**。

**符号必须先钉死**（我第一版写反了，见 `tools/funding_sign_check.py` 的三段证据）：

| # | 证据 | 结果 |
|---|---|---|
| ① | **参照物要对**：资金费比的是「永续 vs **指数价格**」，**不是**「永续 vs rToken 现货」。ticker 同时暴露 `markPrice` 与 `indexPrice`，可直接核对 | 10 个永续**全部**对指数溢价，中位 **+6.33 bp**（正占比 **100%**） |
| ② | **机制方向**：溢价 → 费率为正 → **多头付、空头收**（各主流平台通用，Bitget 费率被 ±0.5% 截断） | — |
| ③ | **实测分布**：6000 次结算的正负占比 | 恰好为 0 **74.2%** ｜ **正 23.9%** ｜ 负仅 **1.9%**；非零中位 **+1.06 ~ +3.21 bp** |
| ④ | ①与③的方向一致性 | **8/10 一致**（两个"不一致"的标的其指数溢价本身≈0，属噪音） |

> ⚠️ **我在这一步犯过两个错，都留了痕**（因为这类错误会整体翻转结论）：
> **(a)** 公式写成 `income = −fundingRate`，方向反了；
> **(b)** 用「永续对 **rToken** 的基差」去交叉验证符号 —— **参照物选错了**，
> 于是 4/10 显示"不一致"。资金费的参照物是**指数**；rToken 现货本身对真实股票
> 就可以有溢价（见 §4.2）。
> **教训：金融量的符号必须用"同参照物"的证据链钉死，不能跨参照物类比。**

机制「逆着溢价走」：**永续溢价 → 费率为正 → 多头付、空头收**。所以：

1. 现货腿**成交率 0.5%–86.5%**（不是"挂了就成交"），且**与点差宽度反向**
2. 现货腿**逆向选择**中位 −0.21 ~ **−21.84 bp**（`HOOD` 最糟，与它 84 bp 的点差规模同量级）
3. `(B_e − B_x)` 在基差平稳时期望为 0 → **本策略赚的是流动性补偿，不是"价差必收敛"**
4. **现货腿是容量瓶颈**（现货成交额 $1.4k–$125k vs 永续 $0.19M–$4.56M）

## 6. 局限（**必须与结论一起读**）

1. **orderbook 快照从 2026-09-13 01:25（北京）才开始**（采样器那时才启动，
   而 `in_house` 窗口 09-12 08:00 就开了）。截至本文件的数据快照
   （09-14 00:04 北京），窗口内盘口覆盖约 **22.6 小时 / 48 小时**；
   窗口前 **17.4 小时**的盘口**永久丢失**（交易所不留存，无法回补）。
   → 所有成交判定与漂移**只覆盖窗口内部分时段**，不得声称全窗口。
   ✔︎ 采样器会继续跑完窗口剩余约 7.8 小时（至 **09-14 08:00 北京** `in_house` 关闭）。
2. **目前覆盖 100% 是 `in_house`，没有 `stockroute` 对照**（`--by-route` 已验证：
   所有成交都落在 `in_house`）。
   ✔︎ **窗口关闭后采样器不停**（设计如此），09-14 → 09-19 这 5 个工作日
   将首次产生 `stockroute` 的现货点差与深度样本 —— **这是本策略"只在周末做"的
   对照组，务必不要再让采样器中断**。下一个 `in_house` 窗口是 09-19（周六）08:00。
   查窗口：`python tools\route_now.py`
3. **`f_dmid(k6)` 只是 3 分钟尺度的漂移**，不等于整个持有期的 `(B_e − B_x)`。
   基差平稳 → 长期期望回到 0；**本文件因此不把 `f_dmid` 当作全部持有期损失**，
   只当作"成交时点"这一项的成本。持有期风险另见 `docs/13` 与 AR(1) 半衰期表。
4. **可捕获额用 `min(现货合计, 永续合计)` 近似**，未做逐笔配对（无严格的同时性约束）。
5. **样本内**：以上全部是 08-22 → 09-14 的样本内结果，**不是样本外**。
6. `SOXL` 现货为**死报价**（bid/ask 冻结 15 小时、`usdtVolume` 逐字节相同），
   已从现货侧排除；它在永续侧的数字仅作参考。
7. 🔴 **rToken 自身的跟踪偏离未纳入净收益判据**（§4.2）。
   用永续的 `indexPrice` 推算，rToken 相对真实股票的偏离在 **−33 ~ +85 bp**，
   **量级大于我们想赚的基差（十几 bp）**。含义是"买现货 / 空永续"的现货腿
   可能买在**已经偏贵**的价位上。**报告必须把它写成已知局限，
   不得声称净收益判据已覆盖全部风险。**
8. **资金费 74.2% 的结算点恰为 0**，收入集中在少数几次非零结算上。
   所以"窗口内 +2.36 bp"是**期望值**，不是稳定现金流；
   单次结算可以为负（实测最差 **−18.91 bp**，出现在 SOXL）。

**注意事项（已踩过的坑）**

- `analyse()` 必须收到**该标的自己的**成交列表；传整本字典会遍历到 key，
  字符串 `'S'` 被当成时间戳（已加 `TypeError` 断言）。
- `csv.DictReader` 读出的一切都是 `str`，比较大小前**必须** `float()`。
- Windows 控制台是 GBK：`−` `×` `→` 这类排版符号会让 `print` 抛
  `UnicodeEncodeError` **并中断整个脚本**。已由 `common/console.py` 的
  `install()` 统一兜底（转写成 ASCII + `errors="replace"`）。
