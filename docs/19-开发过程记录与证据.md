## 4. 工程纪律（都来自真实故障，不是理论）

每一条都有对应的**真实事故**，不是"最佳实践"照抄：

| 纪律 | 触发它的真实事故 | 现在怎么防 |
|---|---|---|
| **绝不重复启动采样器** | 重复实例反复出现，会**把同一份数据写两遍**；且 `Stop-Process` 报成功但进程仍活着 | 四个采样器各自持锁 + 守护自锁 + `taskkill /F` + **重复 `trade_id`** 确凿判据 |
| **"能跑"不等于"功能还在"** | 一次失败的 rebase 后，`window_watch` 静默丢了 **121 行**（整套停摆告警）、`coverage_report` 丢了 **57 行**，而两者**照样能 `--help`、照样退出 0** | 自检第 6 层：**源码特征 + 行为输出**双重钉住 15 项关键能力 |
| **失败 rebase 后必须逐项核对** | 同一次事故里 README 丢了一行链接，我**只 diff 了 README**，漏了工具文件 | `git diff <恢复前提交> HEAD` 逐文件核对删除行 |
| **运行时文件不入库** | `data/logs/*.log` 被进程**持有句柄**，`git pull --rebase` 直接失败（`unable to unlink`），还把工作区文件抹掉了 | `git rm --cached` + `.gitignore` 补全（`.gitignore` **不会**取消已跟踪的文件） |
| **控制台编码兜底** | Windows GBK 下 `print` 到 `−`/`→`/emoji 抛 `UnicodeEncodeError`，**中断整个脚本**，已算完的结果全丢 | `common/console.py` 统一转写 + `errors="replace"` |
| **中文 print 里不嵌 ASCII 直引号** | 同一个语法错误犯了 **5 次**（内层引号提前结束字符串） | `tools/check_nested_quotes.py`；统一改用 CJK 括号「」 |
| **金融量的符号必须用同参照物钉死** | 资金费符号写反（会**整体翻转结论**）；交叉验证时又用错参照物（永续对 rToken ≠ 永续对指数） | 三段独立证据 + 参照物一致性检查 |
| **跨时点相减 = 假发现** | 拿"当前价"比"上次收盘价"，量出 MRVL **−741 bp** 的耸动数字（其实是周末涨跌幅） | 严格同刻对齐；**量级异常大的"发现"先怀疑对齐** |

## 附录 A · 规模统计的复跑命令

```powershell
# 提交数
git rev-list --count HEAD

# 按天提交分布
git log --format=%ad --date=short | Group-Object | Sort-Object Name

# Python 规模（排除 .git / __pycache__ / data）
Get-ChildItem -Recurse -Filter *.py -File |
  Where-Object { $_.FullName -notmatch '\\\.git\\|__pycache__|\\data\\' } |
  Measure-Object -Property Length -Sum

# 自检（最重要的一条）
python tools\reproduce_check.py
```

## 附录 B · 这份记录本身怎么被验证

本文档的**每个数字都来自命令输出**，没有一个是手写的估计值。
如果某个数字变了（例如提交数），重跑附录 A 就能立刻发现。

**这正是本项目对待所有结论的方式** ——
包括那些"我们希望是真的"结论：`docs/14` §4.2 那条被撤回的风险项，
