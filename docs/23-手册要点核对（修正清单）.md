## 🔴 修正 1：项目说明的 6 段结构与 `docs/22` 写的**不一样**

**手册原文的 6 段**（这是表单里那一道大题的结构）：

| 段 | 手册要求 |
|---|---|
| 1 · **思路**（权重最高） | 为什么做这个、核心假设与逻辑。策略类写**信号来源、决策逻辑、风控设计** |
| 2 · **目标用户与产品价值** | 落到具体人群（Retail / VIP / Pro + **风险偏好、资金规模、交易频率、主要市场与场景**）；**不接受「所有 trader」** |
| 3 · **验证数据与关键指标** | 策略类：**测试区间、收益、Sharpe / Sortino、最大回撤、胜率、换手率、手续费滑点等成本**。数字标明**实测 / 估算 / 目标**。再说明**怎么证明被有效使用或分发**（接入数、交易量、AUM、留存） |
| 4 · **完成度** | 做完了什么、还没做什么、遇到的问题与解法、下一步；用了哪些框架 / 模型 / API |
| 5 · **材料清单** | 列出「提交材料链接」里交了什么 |
| 6 · 对 AI Trading 的看法（**选填**） | 使用 Bitget AI 工具的体验与建议 |

**`docs/22` 现有结构是**：问题 / 目标用户 / 数据 / 方法 / 结果 / 局限 ——
**这是"研究论文"结构，不是手册要的结构。**

⚠️ 后果：手册明确「**缺项目说明 → 直接判无效**」；
且「目标用户与验证数据答不全不会判无效，但会明显拉低评审分」。
我们的**第 6 段「局限」在手册里没有对应位置**（局限要并进第 3/4 段），
而**第 4 段「完成度」和第 5 段「材料清单」我们完全没写**。

→ **必须按手册的 6 段重排**（见 `docs/23` 的重排稿）。

## 🔴 修正 2：**两投的正确分法不是"策略 vs 执行"**

用户的质疑（原话）：**「用户获取策略与信号后使用交互执行决策，这不是一套流水线吗？」**
—— **这个质疑是对的。** 把一条流水线砍成两半，
既不符合「每个主题须是独立项目」，也很容易被评委看成灌水。

**手册原文给出的正确落点**：

| 赛道 | 与本项目的关系 |
|---|---|
| **赛道一 Alpha Factory · 开放主题** | 手册**明确点名**：「可参考但不限于：计入手续费、滑点、Funding、冲击成本与策略容量的 **Execution-aware Alpha**」 |
| **赛道三 AI Trading Desk · 具名子主题「执行辅助」** | 手册**明确点名**：「trader 决策后，AI 如何负责**拆单与滑点管理**？—— 大单拆分；**盘口深度分析**；滑点模式调整」 |

**结论：我们做的事同时命中两个赛道，但那是「同一套技术、两个不同赛道」，
而不是「一个项目的两半」。**

**建议方案（修订版）：**

| | 第一次提交 | 第二次提交（如做） |
|---|---|---|
| **赛道** | 🟦 **赛道一 Alpha Factory** | 🟧 **赛道三 AI Trading Desk** |
| **子主题** | **开放主题**（Execution-aware Alpha）或具名「套利」 | 具名 **「执行辅助」** |
| **用户** | 小型量化散户（1k–100k USDT） | **人类 trader** |
| **交付物** | 策略代码 + **回测记录（≥60 天 / OOS ≥30 天）** | **可访问 Demo** + **完整投研任务链路** |
| **评分** | **纯量化评分** | **纯评委主观评分**（功能深度 / 研究质量 / LUI / 个性化主张） |
| **一体化页面** | 策略 → 信号 → 执行 **一条流水线** | 同上页面的「执行辅助」视角 |

> ⚠️ **如果只做一次提交也完全可以**，而且更稳：把执行层作为赛道一开放主题的
> **核心竞争力**（手册点名要求"计入手续费、滑点、Funding、冲击成本与策略容量"——
> 我们恰好全部实测了）。**别为了凑两投而硬拆。**

## 🔴 修正 4：X 帖是**无条件的无效项**

手册原文：
> 提交时须附 **至少 1 条 X 帖链接**，须**转发【待填链接】**，内容需介绍你在构建的产品 / Agent / 策略。
> **无 X 帖 = 提交不完整**；纯转发或无实质介绍 = 提交不完整。

且「什么算无效提交」明确列出：**缺合规 X 帖 / 项目说明 / 可访问的提交材料 → 直接判无效**。

→ `docs/16-X帖草稿.md` 的检查单里**「须转发官方帖」这条要标红**，
且**发帖后再填表**（表单要填链接）。

## ✅ 修正 5：官方工具（MCP / Agent Hub / bitget-signal）—— 我们该用哪些

手册第五章明确列出能力，**很多是免 Key 的**：

| 能力 | 说明 | 我们能不能用 |
|---|---|---|
| **`bitget-signal` 5 个投研 Skill** | **无需账号和 API Key**：`macro-analyst`（宏观/跨资产）、`market-intel`（链上/机构情报）、`news-briefing`（**新闻聚合与叙事合成、关键词搜索**）、`sentiment-analyst`（恐贪/多空比/**资金费率**）、`technical-analysis`（23 指标） | ⭐ **正是我们事件闸门需要的"及时、真实、广泛"来源** |
| **Agent Hub MCP Server** | 一行配置接 Claude Desktop / Cursor / Windsurf | 可用于开发期与 Demo |
| **Tools（89 → 14 intent verbs）** | 行情、现货、合约、账户、借贷… | 行情类可用；我们已有自采数据 |
| **Agentic 账户** | 资金隔离、额度控制、**不可提币**、OAuth 授权 | 若做 Demo 演示用 |
| **`--read-only` / `--paper-trading`** | 安全模式；paper trading 需单独申请 Demo API Key | ⭐ **安全底线，任何时候都该开** |
| **Bitget Playbook** | 自然语言生成策略 + 真实历史回测 | 手册建议 Alpha Factory 用它做回测验证 |

**⚠️ 对我们最重要的一条**：手册说 AI Trading Desk 可组合 `bitget-signal` 做**感知层**。
我们的**事件闸门**正好就是这个位置 —— 应该把数据源从"手敲日历"
换成 **`bitget-signal` 的 `news-briefing` + `macro-analyst`**，
这直接解决 `docs/22` 局限 9 那条「日历 0 条经复核」的缺口。
