## 1. 它带来什么（对应用户的两个诉求）

**① 提高套利效率与准确性**
四个分析师**独立**看四路数据（价格结构 / 情绪 / 事件 / 技术），
覆盖的输入维度比现在单一的成本模型更宽。
尤其是我方**独有**的 5 档盘口 + 逐笔成交（交易所不提供历史接口，别人拿不到），
是这套团队里最难被复制的一路输入。

**② 避免风险**
两层防线：
* **风控官一票否决** —— 事件窗口内禁止挂单，是**硬规则**，LLM 不能推翻；
* **多空辩论** —— 看空研究员专职找漏洞（成交率、逆向选择、容量、腿风险），
  且必须引用**悲观档**而不是只喊"风险高"。

## 2. ⚠️ 四条诚实边界（决定它是"真严谨"还是"看起来严谨"）

多 agent 最容易变成**表演**——把同一个判断换三个说法说出来，显得很严谨但没有任何增量。
我们用四条规则防住它：

### 2.1 辩论必须可证伪

每个 agent 的结论**必须引用一个已实测的量**（点差 / 成交率 / 逆向选择 / 容量 / 资金费），
不能只给"我觉得风险高"。**没有引用的结论不进决策。**

### 2.2 Agent 层只影响边际判断，不改量化基线

费用门槛（11.34 bp）、回测（Sharpe 3.64）、衰减（0.896）全部由**确定性代码**给出。
LLM 有随机性，**不能让它改变可复现的结论** —— 否则报告里的数字无法复跑。
所以：**agent 决定"这一单做不做"，不决定"门槛是多少"。**

### 2.3 不能替代硬门禁

总期 ≥60 天 / OOS ≥30 天 / decay ≥0.5 仍由回测给出（我方 decay = 0.896）。
多 agent 不参与这部分，也不该被写成"用它过了门禁"。

### 2.4 成本与延迟要算清楚

一轮辩论 = 多次 LLM 调用。所以**只在开仓前的少数时点触发**，
不做逐 tick 辩论 —— 逐 tick 既贵又慢，而且我们的采样是 30–60 秒级的，也没有那个必要。

## 3. 实施顺序（在现有代码上增量，不重构）

| 步 | 做什么 | 依赖 | 状态 |
|---|---|---|---|
| 1 | 把 4 个分析师的输出**统一成结构化 schema**（`{dimension, verdict, evidence[], confidence, sources[]}`） | 现有模块 + `signal_adapter` | ✅ 已完成 |
| 2 | 接入 `bitget-signal` 的情绪/新闻/技术三路（免 Key） | 用户环境安装 MCP | ⚠️ **部分**：MCP 已打通、`news_feed` 已验证可调；情绪/技术仍走我方实测（置信度已如实压低） |
| 3 | 实现多空辩论层：**复用双档检验的判据**，让看空方必须引用悲观档 | 步骤 1 | ✅ 已完成 |
| 4 | 交易员/风控官：**直接复用**执行成本模型 + 事件闸门（已实现） | — | ✅ **已完成（2026-09-17）** |
| 5 | 落一份**可复跑的辩论日志**（每题一档，含引用了哪些实测值） | 全部 | ✅ **已完成（2026-09-17）** |

**第 3 步是成败关键**：如果辩论层只是让两个 LLM 互相说意见，就是表演；
必须让它跑在**已经量化的判据**上（P75 点差、实测成交率、逆向选择），才有增量。

### 3.1 第 4–5 步实际怎么落的（`project2/agent_team.py`）
**交易员 = 把「做不做」翻译成可执行订单**，不新造任何阈值：
规模 = min(请求名义额, **可捕获名义额**（`friction_budget.csv` 实测）, **首档深度 × 25%**（自采盘口））；
价位只由**实测半幅点差**给出，不做任何价格预测；拆单笔数 = 规模 ÷ 单笔粒度。

**风控官 = 一张规则表，每条都能独立触发否决**，覆盖闸门管不到的四类风险：

| 规则 | 级别 | 触发（全部是实测量） | 处置 |
|---|---|---|---|
| `gate_block` | 否决 | 闸门 severity=`block` | 不开新仓 |
| `debate_stand_down` | 否决 | 辩论裁决 `stand_down` | 不开新仓 |
| `cost_exceeds_edge` | 否决 | 最优执行成本 > 11.34 bp **且**毛边际 < 11.34 bp | 不开新仓 |
| `adverse_selection` | 否决 | 现货腿 f_dmid ≤ −3.0 bp | 不开新仓 |
| `thin_capacity` / `thin_depth` | 警示 | 容量 < 1,000 USD ／ 单笔 > 首档 25% | 缩规模 |
| `leg_risk_high` | 警示 | P(只成交一腿) > 50% | 强制双腿全吃单 |
| `no_capacity_data` / `no_cost_data` | 警示 | 数据缺失 | 不开新仓（**数据缺失 ≠ 没有风险**） |

🔴 **单调性**（自检 3 立场 × 3 闸门状态穷举验证）：
`最终立场 ≤ 辩论立场`，`最终规模 ≤ 交易员规模 ≤ 风控规模上限` ——
交易员与风控官**只能收紧，不能放松**。这一条是"一票否决"能不能算数的分界线。

### 3.1.1 🔴 后续修正（2026-09-18）：agent 到底做哪些环节

初版把"辩论层 + 交易员 + 风控官"整体说成"agent 层"，**这是不准确的**。
现在明确分成两侧，并且**都写进代码注释与 README**：

| 环节 | 谁做 | 依据 |
|---|---|---|
| 5 路独立分析（新增第 5 路**执行风险评估**） | **agent** | 需要把跨表事实联系起来（例：现货报价在动、但 4 天无成交） |
| 多空立论 / 交叉质证 / **提出风险假设** | **agent** | 产出"假设 + 实测量 + 阈值 + 证伪条件" |
| 事件判断 | **LLM**（运行期唯一职责） | 非结构化输入；无 key 时**如实标注"本次未使用 LLM"** |
| 成本数字 / 最优执行方式 / **一票否决** / 最终规模 | **确定性代码** | 门槛与规模必须可复跑（`--replay` 逐字节比对） |

**新增的第 5 路（`analyst_execution_risk`）**是"agent 做风险评估"的落地：
它不碰数字，只把"这一单可能怎么死"组织成**可证伪的假设**，
覆盖四类实测踩过的坑：单腿裸露 / **行情停滞** / 容量约束 / 逆向选择。
每条假设四要素缺一不可（假设、实测量、验证阈值、证伪条件），
缺证的直接丢弃并留痕。

**闭环**：假设经 `HYPOTHESIS_ACTIONS` 映射成风控动作（日志里以 `agent:` 前缀标识），
风控官**当作规则执行**，但**仍受同一条单调性约束**。
实测：`agent:stale_quotes`（现货腿 6679 分钟无成交）**真的触发了一票否决**
（`agent_driven: true`）。自检里两条专门盯这个：
① agent 的假设确实能改变决策；② **没有假设时不产生 agent 规则**（防它变成万能借口）。

⚠️ 同一轮还修掉一个**"说了没做"**：`analyst_news` 此前**硬编码 `mode="static"`**，
于是 `event_gate.llm_gate()` 虽然写好了**却从未在决策链里跑过**，
而报告里写着"LLM 在运行期的唯一职责 = 事件判断"。
现在按 `mode` 分流（static / llm / auto），且**LLM 没成功执行时会在 notes 里明写**
（含"未配置 key"这一情形）；能取到标题时走真 LLM。
⚠️ 仍然存在的限制：`bitget-signal` 的 `news_feed` 对**全部 44 个源返回空 items**
（`signal_adapter.py` 实测记录），所以即便配了 key，**也没有真实标题可喂** ——
这一条必须与"LLM 已接入"的说法一起出现，不能只说前半句。

⭐ **为什么成本否决条是「成本越线 **且** 毛边际不足」**：
毛边际（basis 净收益 + 资金费）是**项目一的策略结论**，它的门槛属于研究层；
只凭它下结论就等于风控官替研究层拍板了。加上"成本这一侧"，
否决才完全建立在**执行层**的事实上。两侧用的是**同一个已实测阈值**（11.34 bp），
不新造数字 —— 这条规则改过一版：初版自己造了条 3 bp 红线，那违反"不新造阈值"。

### 3.2 第 5 步：可复跑日志怎么"把话说死"一份 `data/reports/debate-<base>-<ts>.json` 含：参数与**全部阈值**、输入文件的
**SHA256 清单**、四层完整留痕（分析师证据 / 辩论论点与**证伪条件** / 交易员订单 /
风控官 **9 条规则逐条留痕**）、以及 `decision_hash`。

复跑判定**分成两类**，不含糊说"通过"：

| 类别 | 字段 | 要求 |
|---|---|---|
| **契约字段** | 参数 / 规则表 / 最终立场 / 最终规模 / 订单方式 / 风控降级路径 / 单调性 | **必须一致**，否则 `--replay` 退出码 1 |
| **实时量** | 盘口快照、点差、成本、规则实测值 | 允许漂移（采样器在持续写入），但**如实列出** |

另有**诚信校验**：日志内容重算哈希与其记录的 `decision_hash` 比对。
自检用"篡改 `final_qty_usd`""删掉一条风控规则"两个用例验证它抓得住 ——
实测踩到过：少了这一步时，"记录哈希"与"复跑哈希"可能拿的是同一个**没重算过**的字段，
于是被改过的日志照样显示"一致"。

复跑命令：
```powershell
python project2\agent_team.py --base NVDA --trader --log
python project2\agent_team.py --replay data\reports\debate-NVDA-<ts>.json
python project2\agent_team.py --selfcheck     # 四层全部自检，无需网络
```

## 4. 与手册的关系（为什么这适合"赛道一 · 开放主题"）

* 手册的开放主题**点名**了「**Execution-aware Alpha**」——计入手续费、滑点、Funding、
  冲击成本与策略容量。**我们全部实测了**，这是现成的核心竞争力。
* 手册说「大模型在项目中的作用」要填"信号推理、Agent 决策等"——
  这套多 agent 架构正好给出**运行期的真实用途**，而不是只有开发期。
* 手册提示 AI Trading Desk 可组合 `bitget-signal` 做感知层；
  我们把它用在**风控感知**上，位置更明确。

**⚠️ 但要注意**：这套东西的**加分点在于"判断质量"，不在于"agent 数量"**。
报告里不该写"我们用了 9 个 agent"，而该写
"我们让看空方必须引用悲观档与实测成交率，因此辩论是可证伪的"。

**自检覆盖的失败模式**（不是"跑通了"，是"跑错了会被抓住"）：
无证据的结论作废 / 无证伪条件的论点作废 / 同一证伪条件重复计分被折叠 /
方向自相矛盾的论据被扣分 / 闸门 block 时辩论压不过硬规则 /
风控 9 条规则都能独立触发 / **交易员与风控官只能收紧**（9 组穷举）/
同输入两次决策完全一致 / 篡改日志与删规则都能被复跑校验抓出。
