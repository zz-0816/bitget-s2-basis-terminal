## 0. 结论：**可行**，而且绝大部分组件我们已经有了

用户提出的设想是参考证券分析团队的分工（分析师 4 维度 → 研究员多空辩论 → 决策团队风控执行）
做多 agent 协作。评估下来：

**这不是从零造，而是「把已有组件 agent 化 + 加一层可证伪的辩论」。**

## 1. 它带来什么（对应用户的两个诉求）

**① 提高套利效率与准确性**
四个分析师**独立**看四路数据（价格结构 / 情绪 / 事件 / 技术），
覆盖的输入维度比现在单一的成本模型更宽。
尤其是我方**独有**的 5 档盘口 + 逐笔成交（交易所不提供历史接口，别人拿不到），
是这套团队里最难被复制的一路输入。

**② 避免风险**
两层防线：
* **风控官一票否决** —— 事件窗口内禁止挂单，是**硬规则**，LLM 不能推翻；
* **多空辩论** —— 看空研究员专职找漏洞（成交率、逆向选择、容量、腿风险），
  且必须引用**悲观档**而不是只喊"风险高"。

## 2. ⚠️ 四条诚实边界（决定它是"真严谨"还是"看起来严谨"）

多 agent 最容易变成**表演**——把同一个判断换三个说法说出来，显得很严谨但没有任何增量。
我们用四条规则防住它：

### 2.1 辩论必须可证伪

每个 agent 的结论**必须引用一个已实测的量**（点差 / 成交率 / 逆向选择 / 容量 / 资金费），
不能只给"我觉得风险高"。**没有引用的结论不进决策。**

### 2.2 Agent 层只影响边际判断，不改量化基线

费用门槛（11.34 bp）、回测（Sharpe 3.64）、衰减（0.896）全部由**确定性代码**给出。
LLM 有随机性，**不能让它改变可复现的结论** —— 否则报告里的数字无法复跑。
所以：**agent 决定"这一单做不做"，不决定"门槛是多少"。**

### 2.3 不能替代硬门禁

总期 ≥60 天 / OOS ≥30 天 / decay ≥0.5 仍由回测给出（我方 decay = 0.896）。
多 agent 不参与这部分，也不该被写成"用它过了门禁"。

### 2.4 成本与延迟要算清楚

一轮辩论 = 多次 LLM 调用。所以**只在开仓前的少数时点触发**，
不做逐 tick 辩论 —— 逐 tick 既贵又慢，而且我们的采样是 30–60 秒级的，也没有那个必要。

## 3. 实施顺序（在现有代码上增量，不重构）

| 步 | 做什么 | 依赖 |
|---|---|---|
| 1 | 把 4 个分析师的输出**统一成结构化 schema**（`{dimension, verdict, evidence[], confidence, sources[]}`） | 现有模块 + `signal_adapter` |
| 2 | 接入 `bitget-signal` 的情绪/新闻/技术三路（免 Key） | 用户环境安装 MCP |
| 3 | 实现多空辩论层：**复用双档检验的判据**，让看空方必须引用悲观档 | 步骤 1 |
| 4 | 交易员/风控官：**直接复用**执行成本模型 + 事件闸门（已实现） | — |
| 5 | 落一份**可复跑的辩论日志**（每题一档，含引用了哪些实测值） | 全部 |

**第 3 步是成败关键**：如果辩论层只是让两个 LLM 互相说意见，就是表演；
必须让它跑在**已经量化的判据**上（P75 点差、实测成交率、逆向选择），才有增量。

## 4. 与手册的关系（为什么这适合"赛道一 · 开放主题"）

* 手册的开放主题**点名**了「**Execution-aware Alpha**」——计入手续费、滑点、Funding、
  冲击成本与策略容量。**我们全部实测了**，这是现成的核心竞争力。
* 手册说「大模型在项目中的作用」要填"信号推理、Agent 决策等"——
  这套多 agent 架构正好给出**运行期的真实用途**，而不是只有开发期。
* 手册提示 AI Trading Desk 可组合 `bitget-signal` 做感知层；
  我们把它用在**风控感知**上，位置更明确。

**⚠️ 但要注意**：这套东西的**加分点在于"判断质量"，不在于"agent 数量"**。
报告里不该写"我们用了 9 个 agent"，而该写
"我们让看空方必须引用悲观档与实测成交率，因此辩论是可证伪的"。
