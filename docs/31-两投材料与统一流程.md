## 0. ⚠️ 先说清楚一条不能碰的硬规则

手册原文（我们 09-12 就抄录过，`docs/00` §2）：

> 「一支队伍最多向 **2 个不同主题**提交，**每个主题须是独立项目，分两次填表**。」

**所以"合成一项提交"是不允许的** —— 那不是"串联"，是三个具体风险：

| 风险 | 后果 |
|---|---|
| 只填一份表 | 等于放弃第二个主题的参评资格（而我们**已经**有可交付的第二个项目） |
| 把两个项目写成一份材料 | 与"每个主题须是独立项目"直接冲突，可能被判违规 |
| 但把交互也拆成两套 | 用户要在两个页面之间来回看，**体验上确实是"两个半成品"** |

✅ **正确做法（也正是用户想要的）**：**交互合并成一条流程，提交仍分两份**，
每份材料里都写清与另一份的接口。这样既满足硬规则，用户看到的又是一条完整的链。

## 1. 一条流程，两个项目 —— 交接点在哪

```
                     ┌──────────────── 项目一：Alpha Factory ────────────────┐
  自采数据（不可回补） │  盘口 5 档 · 逐笔成交 · 全池轮转 · K 线                  │
  ──────────────────>│                                                      │
                     │  ① 哪里有价差？        → 基差 / 点差 / 成交额          │
                     │  ② 哪个口径才可执行？  → route=in_house 才省点差        │
                     │  ③ 成本门槛 11.34 bp   → 越线率 38.4% vs 13.2%         │
                     └───────────────────────┬──────────────────────────────┘
                                             │ 只读引用（单向）
                                             │ · data/spread/* 盘口
                                             │ · data/derived/* 成本参数
                                             │ · common/market_calendar 口径
                                             ▼
                     ┌──────────────── 项目二：Execution-aware Alpha ────────┐
                     │  ④ 这一单怎么下？     → 双腿三方案 + 实测联合分布      │
                     │  ⑤ 现在有没有事件？   → 事件闸门（LLM 唯一职责）       │
                     │  ⑥ 谁说了算？         → 风控官**一票否决**，只收紧      │
                     │  ⑦ 凭什么信？         → 可复跑辩论日志 + --replay      │
                     └──────────────────────────────────────────────────────┘
```

**七个交接点**（这是"串联"的实质，不是口号）：

| # | 交接内容 | 项目一的产出 | 项目二的用法 | 可验证处 |
|---|---|---|---|---|
| 1 | **盘口** | `data/spread/orderbook-*.csv`（30 秒 5 档） | 算冲击、算首档深度约束 | `project2/execution_cost.py` |
| 2 | **点差与中间价** | `data/spread/2026-*.csv` | 定挂单价位（中价 ± 半幅点差） | 同上 |
| 3 | **成交率与逆向选择** | `data/derived/precise_fill_*.csv` | 成交概率、逆向选择期望 | `docs/14` §3 |
| 4 | **联合成交分布** | `tools/joint_fill_analysis.py` 实测 | `P(两腿)/P(只一腿)/P(都没)` | `docs/14` §9 |
| 5 | **口径（route/session）** | `common/market_calendar.py`（唯一实现） | 按 route 取分层成交概率 | 只调用不修改 |
| 6 | **事件日历** | `project2/events_calendar.json` | 闸门硬否决挂单 | `project2/event_gate.py` |
| 7 | **执行结论回流** | 项目一可选择性引用 | 项目二输出执行建议 | `docs/22` 补充说明 |

🔴 **反向依赖为零**：把 `project2/` 整个目录删掉，项目一照样完整运行
（`python tools\reproduce_check.py` 仍应 0 失败）。这是"独立项目"的硬要求，
也是我们敢分两份表提交的依据。

## 2. 统一入口：一条命令 / 一个页面

### 2.1 命令行（给复核与评委，不需要浏览器）

```powershell
python tools\unified_demo.py --base NVDA
```

按顺序打完整条链：① 策略与信号 → ② 执行决策（含腿风险深挖）→ ③ 多 Agent 团队
（分析师证据数 → 辩论 stance → 交易员订单 → 风控官裁决 → 最终决策 + 单调性校验），
末尾给出每一步的**单独复跑命令**。

### 2.2 页面（给用户）

`web/` 是**同一个页面两个视角**，已在仓库里：

| 页面区块 | 回答 | 属于 |
|---|---|---|
| 策略窗口 / 同一标的两场所 / 基差时序 / 分时段点差 | **哪里**有价差 | 项目一 |
| **执行决策·风险与理由** | 这一单**该不该做、为什么、什么条件** | 项目二 |
| 数据状态 | 诚实标注局限 | 两者 |

启动：`python server\app.py --port 8787` → http://127.0.0.1:8787
（已实测在跑：`/api/health` 返回 200）
