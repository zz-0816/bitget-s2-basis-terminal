**一次真实决策的流向示例**（NVDA，2026-09-18 实测）：

```
5 路分析(5/5 有效) → 辩论 stance=stand_down(空头0.95 vs 多头0.70)
  → 闸门 severity=caution（triple witching）
  → 交易员：stand_down 不下单
  → 风控官：reject（debate_stand_down + agent:stale_quotes）
  → 最终：stand_down ｜ 0 USD ｜ 单调性校验通过
                     ↑
        agent 驱动的那一票：现货腿 6679 分钟无成交
```

## 1. 逐 agent 规格表（v1 草案 —— **这一节是等你补充的地方**）

图例：`P` = 现有实现里已经稳定的部分；`⚠️` = 需要你补充/确认的部分

### ①-a 📊 基差基本面分析师 `analyst_basis`

| 项 | 内容 |
|---|---|
| **职责** | 回答"这个价差扣掉成本之后还剩多少" |
| **输入（只读）** | `data/derived/friction_budget.csv`（半幅点差、往返净收益、可捕获名义额）、`data/derived/funding_rates.csv`（48h 资金费收入）、`execution_cost` 的最优成本 |
| **输出** | `{dimension, verdict, confidence=0.80, evidence[], sources[], notes}` |
| **判据（P）** | `净收益 + 资金费 > 3 bp` → favorable；`< 0` → unfavorable；否则 neutral |
| **证据铁律（P）** | 每条证据必须 `metric + value + source`，缺一即被 `validate()` 判无效 |
| ⚠️ **待你补充** | 阈值 3 bp 的来源要不要换成"门槛 11.34 bp"？现在两个数并存，容易让读者困惑 |
| ⚠️ **待你补充** | 是否加入 **RAG**：把 `docs/13`/`docs/14` 的判据段落检索进来，让 agent 引用"我们自己的口径" |

### ①-b 😱 情绪分析师 `analyst_sentiment`

| 项 | 内容 |
|---|---|
| **职责** | 持仓拥挤度 / 谁在付费 |
| **输入（P）** | `funding_rates.csv`：正费率占比、非零结算费率中位 |
| **现状（P）** | **未接 bitget-signal**（实测 `news_feed` 44 源全空），置信度如实压到 **0.45** |
| ⚠️ **待你补充** | 替代源：永续**多空持仓比 / 主动买卖量 / 未平仓量** 是否可自采？比"资金费代理"更直接 |
| ⚠️ **待你补充** | prompt：如果接入 LLM，情绪这一路该问什么、**不许**问什么（防止它编故事） |

### ①-c 📰 新闻/事件分析师 `analyst_news`

| 项 | 内容 |
|---|---|
| **职责** | "现在是不是信息事件窗口"（**LLM 在运行期的唯一职责**） |
| **输入（P，已是本次新增）** | `tools/news_sources.py`：SEC EDGAR 一手申报 / Fed·SEC·BEA 官方RSS / Nasdaq 财报日历 / Yahoo·CNBC 聚合RSS → 筛出候选标题 |
| **输出（P）** | `{severity: none/caution/block, reason, confidence, source}` |
| **置信度规则（P）** | 有可回溯来源 → 0.85；否则封顶 **0.40** |
| **降级行为（P）** | 无 key / LLM 失败 → 退回确定性日历，**并在 notes 明写"本次未使用 LLM"** |
| ⚠️ **待你补充** | **prompt 版本**：现在是 5 行分类 prompt（`event_gate.LLM_PROMPT`），要不要加 few-shot / 标的上下文（市值、板块、历史财报日）？ |
| ⚠️ **待你补充** | **RAG**：是否把"过去 30 天已判过的事件 + 人工复核结果"做成检索库，做一致性校准？ |
| ⚠️ **待你补充** | 成本控制：候选标题 12 条/轮 × 每分钟 ≈ 17k 次/天。要不要改**事件驱动**（只在 EDGAR 出现新申报 / 日历命中时才调 LLM）？ |

### ①-d 📈 技术面分析师 `analyst_technical`

| 项 | 内容 |
|---|---|
| **职责** | 盘口形状 + 成交率 + 逆向选择（**这一路是我们独有的**：盘口无历史接口） |
| **输入（P）** | `data/spread/orderbook-*.csv`（5 档）、`precise_fill_spot_bid.csv`（成交率、f_dmid） |
| **输出（P）** | verdict 由 `成交率 <10% 或 f_dmid < −3bp → unfavorable` 决定 |
| ⚠️ **待你补充** | 是否加**盘口不平衡**（bid/ask 深度比）、**撤单率**、**价差时序波动**等更细的形状指标？ |
| ⚠️ **待你补充** | 现在阈值（10% / 30% / −1 / −3 bp）是硬编码，要不要做成可配置并写进冻结清单？ |

### ①-e 🛡️ 执行风险分析师 `analyst_execution_risk`（**本次新增**）

| 项 | 内容 |
|---|---|
| **职责** | 不回答"哪路数据怎么样"，只回答 **"这一单可能怎么死"** |
| **输入（P）** | 联合分布 `joint_fill_*.csv`、**`trades-*.csv` 的最后成交时间**、可捕获名义额、f_dmid |
| **输出（P）** | `{hypotheses:[{id, hypothesis, metric, value, threshold, falsifier, action}], dropped[]}` |
| **四要素铁律（P）** | 假设 · 实测量 · 验证阈值 · **证伪条件** —— 缺一即丢弃并留痕 |
| **上限（P）** | 最多 3 条进辩论/风控（`MAX_HYPOTHESES`，防刷屏式围堵） |
| **闭环（P）** | 假设 → `HYPOTHESIS_ACTIONS` → 风控规则（`agent:` 前缀）→ 可真正否决 |
| ⚠️ **待你补充** | 现在的 4 类（单腿裸露/行情停滞/容量/逆向选择）**够不够**？还想加什么风险维度？ |
| ⚠️ **待你补充** | prompt：如果给这个 agent 配 LLM，它该**只做假设生成**还是也做**优先级排序**？（我倾向只做前者） |

### ② 🐂🐻 多空辩论层 `argue` / `cross_examine` / `adjudicate`

| 项 | 内容 |
|---|---|
| **职责** | 同一批证据，强制两边各自立论并互相质证 |
| **立论规则（P）** | 只引用**与自己立场一致**的结论；按**证伪条件分组**（同一证伪条件只出 1 条论点） |
| **交叉质证（P）** | 每方必须**指名对方最强的一条**并复述其证伪条件 —— 让"各说各话"在结构上不可能 |
| **裁决（P，确定性）** | 得分差 ≥0.25 → 有倾向；否则 caution。方向自相矛盾扣 0.15/条 |
| ⚠️ **待你补充** | 得分 = Σ置信度 是否太粗？要不要按**证据强度**（实测 vs 推断）加权？ |
| ⚠️ **待你补充** | 僵持阈值 0.25 是拍的，是否用历史决策做一次校准？ |

## 2. 三条设计红线（补充内容不能破这三条）

| # | 红线 | 为什么 |
|---|---|---|
| 1 | **agent 不产出数字**（规模/价位/门槛） | 否则 `--replay` 失效、报告里的数字无法验证 |
| 2 | **agent 只收紧，不能放松** | 风控若能让 agent 说了算，"一票否决"就成装饰 |
| 3 | **任何结论都要有实测量 + 证伪条件** | 这是本项目对抗"多 agent 表演化"的唯一手段（`docs/25` §2.1） |

> 补充 prompt / RAG / 工具时，只要不破这三条，实现上都能接。
