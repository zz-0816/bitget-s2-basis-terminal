## 0. 一句话定位（先说清"为什么这是一个项目，而不是项目一的附录"）

> **项目一回答「哪里有价差」；项目二回答「这一单怎么下、能不能下」。**
> 项目二的核心不是又一个成本公式，而是**一个会自我质疑的 agent 团队**：
> 5 路独立分析 → 多空辩论 → 交易员出方案 → 风控官一票否决，
> 每一步都必须引用**已实测的量**，每一句结论都必须能被**证伪**。

**与"再包装一层 agent"的区别**（这是评委会追问的点）：

| 常见的多 agent 演示 | 我们做的 |
|---|---|
| 几个 LLM 各说一段话，听起来都很像样 | 结论必须引用**实测值**（缺证直接作废） |
| 两边各说各话，没人能判对错 | 每条论点必须给**证伪条件**（给不出即没收） |
| 同一个判断换三个说法显得很严谨 | **同一证伪条件只算一条**（防灌水，有自检） |
| LLM 决定"做多大、挂哪个价" | **agent 只做发现与论证；数字与否决权在确定性代码** |

## 第 1 段 · 思路（权重最高）

### 1.1 为什么做这个

项目一已经证明：跨场所价差**只在**平台「所内撮合」窗口（周末/节假日）具有零售可执行性，
而且**唯一收益来源是流动性补偿**（做市），不是"价差必收敛"。

但项目一能算"能不能赚"，**算不出"这一单该怎么下"**：

| 执行层的真实问题 | 为什么单靠成本公式答不了 |
|---|---|
| 这一刻挂单，**会不会被逆向选择**？ | 需要把"现在有没有信息事件"这件事**从非结构化新闻里读出来** |
| 两条腿**只成交一条**怎么办？ | 需要知道**联合**成交分布，不是两条腿各自的成交率 |
| 报价在动，**但市场还有成交吗**？ | 需要把"报价"和"逐笔成交"两张表**联起来**看 |
| 出了这么多风险信号，**谁说了算**？ | 需要一个能**一票否决**、且**只收紧不放松**的风控角色 |

### 1.2 核心假设与决策逻辑（agent 团队）

**假设 H1**：执行决策的输入是**多维度、非结构化、且相互冲突**的，
因此需要**多个独立视角**分别取证，再由一个**强制对抗**的辩论层收敛。

**假设 H2**：但**数字不能由 LLM 生成** —— 否则报告里的每个数字都无法复跑。
所以把系统切成两半：

| 谁 | 做什么 | 为什么 |
|---|---|---|
| **agent（5 路分析 + 辩论 + 风险假设）** | **发现与论证** | 需要把跨表事实联系起来；规则写不全 |
| **LLM（仅事件判断一处）** | 从新闻/申报里判断"是不是信息事件" | 输入是非结构化的 |
| **确定性代码（成本/执行方式/一票否决/最终规模）** | **执行与守边界** | 门槛与规模**必须可复跑**（`--replay` 逐字节比对） |

**决策逻辑**（每一步都可单独复跑）：

```
5 路独立分析 ──┬─ 📊 基差成本      （实测：摩擦预算、资金费）
（互不读对方）  ├─ 😱 情绪拥挤度    （实测：资金费结构）
               ├─ 📰 事件/新闻     （LLM 唯一的活：SEC 申报 / 官方 RSS / 财报日历）
               ├─ 📈 盘口与成交    （我方独有：5 档盘口 + 逐笔成交）
               └─ 🛡️ 执行风险      （agent 做的风险评估：把四类"怎么死"写成可证伪假设）
                      ↓ 只保留有实测量的结论（无证据 → 作废）
               🐂 多头立论  ⇄  🐻 空头立论        （每条论点必须给证伪条件）
                      ↓ 交叉质证：必须指名对方最强一条并复述其证伪条件
               裁决（确定性）：得分差 ≥0.25 才有倾向，否则"僵持 = caution"
                      ↓
               事件闸门（LLM）：severity=block → **挂单类方案直接作废**（硬规则）
                      ↓
               交易员：规模/价位/方式/拆单（不新造阈值、不做价格预测）
                      ↓
               风控官：9 条固定规则 + **agent 假设驱动的规则** → 一票否决/缩规模/强制吃单
                      ↓
               最终决策 + **可复跑日志**（参数、阈值、输入 SHA256、decision_hash）
```

### 1.3 风控设计（本项目的核心差异点）

**两条线同时管**，缺一条都不成立：

1. **硬规则（代码）**：事件窗口内禁挂单、成本越线且边际不足则否决、
   逆向选择过深则否决、数据缺失按最保守处理（**缺数据 ≠ 没有风险**）。
2. **agent 提出的风险假设**：每条带**实测量 + 阈值 + 证伪条件**，
   经映射变成可执行的风控动作，日志里以 `agent:` 前缀标识。

🔴 **单调性硬约束**（自检里 3 立场 × 3 闸门状态穷举验证）：
`最终立场 ≤ 辩论立场`，`最终规模 ≤ 交易员规模 ≤ 风控规模上限` ——
**任何一环只能收紧，不能放松**。这一条是"一票否决"能不能算数的分界线。

## 第 2 段 · 目标用户与产品价值

> 手册要求：**具体画像**，**禁止写"所有 trader"**。

### 2.1 目标用户（具体画像）

**主用户：已经被"执行成本"吃过亏的**泛散户 / 小资金主动交易者**

| 特征 | 说明 |
|---|---|
| 资金规模 | 单笔 1k–50k USD（再大就撞上容量约束，见第 6 段） |
| 交易习惯 | 会在**休市时段**看行情、想提前建仓美股敞口 |
| 痛点 | 下单后发现"点差 + 滑点 + 资金费"把预期收益吃光；**不知道是该挂还是该吃** |
| 不满足于 | "帮我预测涨跌" —— 他们要的是**这一单怎么下** |

**次用户（与项目一共享）**：已有多平台仓位、会写脚本的小型量化散户。

### 2.2 产品价值（可验证，不是口号）

| 价值 | 可验证形式 |
|---|---|
| 把"该吃还是该挂"变成**有依据的选择** | 三种执行方式的成本并排 + **逐条证据** |
| 把"风险"变成**可证伪的清单** | 每条风险给出实测量、阈值、撤销条件 |
| **不代下单**，输出理由与条件 | `assess()` 输出 rationale / warnings / conditions |
| 决策**可复跑、可审计** | `--log` + `--replay`（契约字段逐字节比对） |

## 第 4 段 · 方法（含"最快的消息面"）

### 4.1 事件源：我们能做到多快，以及为什么不能再快

| 层级 | 源 | 事件到我们能看见的典型延迟 | 为什么选它 |
|---|---|---|---|
| **① 一手** | **SEC EDGAR**（8-K/10-Q/10-K/Form 4） | **分钟级** | 财报与重大事项**法定首先申报在这里**；有 JSON 接口、无需 key |
| ② 官方 | Fed / SEC / BEA 新闻稿 RSS | 分钟~小时 | 宏观事件的第一落点 |
| ③ 日历 | **Nasdaq 财报日历** | **提前数天** | 不是事件流而是**预告** —— 能**提前避开**，价值最高 |
| ④ 聚合 | Yahoo / CNBC RSS | 分钟~小时 | 二级转述，快但会重复、会滞后 |
| ⑤ 情绪 | bitget-signal MCP | ⚠️ **当前不可用**（44 源全空） | 如实标注，不假装 |

**三条必须一起说的边界**：

1. **我们不是毫秒级**：真实延迟 = 源延迟 + 轮询间隔，而**我们的采样器本身是
   30–60 秒节奏** ——所以"再快"在观察上也没有意义。我们的目标是
   **"以一手源为主、按分钟级发现"**，而不是假装高频。
2. **EDGAR 只覆盖法定披露**：社交媒体传闻、盘中快讯不在其中（那类只能靠聚合源，必然滞后）。
3. **iXBRL 全文检索有约 10 分钟索引延迟**，因此优先用"最新申报列表"而非全文检索。

### 4.2 agent 团队的分工与铁律

| 层 | 铁律（结构上防住失败模式） |
|---|---|
| 5 路分析师 | **没有引用已实测的量的结论一律作废** |
| 多空辩论 | **给不出证伪条件的论点一律作废**；同一证伪条件不得重复计分；方向矛盾扣分 |
| 交易员 | **不新造阈值**：规模 = min(请求, 可捕获名义额, 首档深度×25%) |
| 风控官 | 每条规则都要回答"引用什么/触发做什么/**什么条件下撤销**"；未触发的也留痕 |

⭐ **一个真实闭环（可复跑）**：`execution_risk` 分析师发现
**现货腿报价仍在刷新、但最后一笔成交是 6679 分钟前（4.6 天）** ——
"报价在动 ≠ 能成交"，而挂单策略的收益**完全来自成交**。
这条假设以 `agent:stale_quotes` 进入风控，**真的触发了一票否决**
（日志字段 `agent_driven: true`）。盘口数据（点差、深度）**完全看不出**这件事。

### 4.3 可复跑（这是"严谨"的落地，不是形容词）

`--log` 落一份日志：参数 + **全部阈值** + 输入文件 **SHA256** + 四层留痕 + `decision_hash`。
`--replay` 重跑并**分两类比对**：

| 类别 | 字段 | 要求 |
|---|---|---|
| **契约字段** | 参数 / 规则表 / 最终立场 / 最终规模 / 订单方式 / 降级路径 / 单调性 | **必须一致**，否则退出码 1 |
| **实时量** | 盘口、点差、成本、规则实测值 | 允许漂移（采样器在写），但**如实列出** |

另有**诚信校验**：日志内容重算哈希与其记录比对（自检用"篡改规模""删一条规则"验证它抓得住）。

## 第 6 段 · 局限（**主动写，这是可信度来源**）

| # | 局限 | 说明 |
|---|---|---|
| 1 | **现货腿自 09-14 起零成交** | 上游报价仍在刷新，但逐笔成交为 0 已 4 天 → "现货挂单赚点差"当前**不可执行**；这也意味着真实腿风险**比 24.9% 更差** |
| 2 | **联合分布只覆盖 09-12~09-14** | 现货成交带的最后三天，且是**分布**不是逐笔 |
| 3 | **双腿成交相关性**已实测取代近似，但样本只有三天 | 结论方向可信，量级需更多样本 |
| 4 | **容量是制度性 + 流动性双重限制** | 实测现货腿成交额仅为永续的 1/20~1/300；且监管豁免**明确限制符号数量与成交量**（`docs/32`） |
| 5 | **事件源不是毫秒级**；EDGAR 只覆盖法定披露 | 见 §4.1 三条边界 |
| 6 | **LLM 未配置 key 时退化为确定性日历** | 会在输出里**明确标注"本次未使用 LLM"**，只挡得住可计算事件（期权到期/休市） |
| 7 | **bitget-signal 的 news_feed 当前 44 源全空** | 已实测记录；替代源见 §4.1 |
| 8 | **无挂单队列位置模型** | 成交概率用历史实测率近似，不含排队位置 |
| 9 | **监管豁免 5 年后到期、且正在征求意见** | 策略有明确的制度性时间窗（`docs/32`） |
| 10 | **采样缺口**：8.04 小时（09-16/17）+ 74.9 分钟（09-18） | 两次**均 100% 落在 `stockroute`**，`in_house` 0 分钟 |
