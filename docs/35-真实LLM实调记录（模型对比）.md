## 1. 实测结果

| 案例（期望） | `deepseek-v4-pro` | `deepseek-flash` |
|---|---|---|
| 8-K 发布季度业绩（**block**） | block ✅ | block ✅ |
| 例行内部人交易 Form 4（**none**） | none ✅ | none ✅ |
| Nasdaq 100 指数权重调整（caution） | **none ❌** | caution ✅ |
| 分析师下调目标价（caution） | caution ✅ | caution ✅ |
| Fed FOMC 决议（caution） | caution ✅ | caution ✅ |
| 纯营销内容（**none**） | none ✅ | none ✅ |
| **SEC 代币化股票创新豁免**（**block**） | **caution ❌** | block ✅ |
| **判定一致率** | **5/7** | **7/7** |
| **延迟 中位 / 最大** | 1.20s / 1.51s | **0.84s / 0.96s** |
| tokens（7 案例合计） | 输入 2,286 / 输出 336 | 输入 2,307 / 输出 372 |

**v4-pro 的两次偏离都偏"不够保守"**，而且理由很有代表性：

| 案例 | v4-pro 给出的 reason |
|---|---|
| 指数调整 | 「指数权重调整属于市场结构性事件，**与 NVDA 基本面无关**」 |
| SEC 豁免 | 「监管新规涉及代币化股票交易，可能影响市场结构，**但标题未明确对 NVDA 的具体影响，信息不足**」 |

**这不是随机错误，是"推理过度"**：模型用"与标的基本面无关"当作降级理由，
把分类任务当成了需要论证的判断题。而我们的判据是**按事件类别分级，
不是按"对某个标的的相关性"分级**：

* 指数调整会改变被动资金的流向与流动性结构 → 对我们（做市/赚点差）**直接相关**，应 caution
* SEC 代币化股票豁免**直接改变我们所在市场的规则** → 应 block

---

## 2. 结论：**用 flash，不用 pro**

三条理由（前两条是实测，第三条是设计）：

1. **一致率 7/7 vs 5/7**，且 pro 错在**"不够保守"**这一侧 ——
   对我们来说漏判（block→none/caution）比误判（none→block）**贵得多**：
   误判只会让我们少做一些机会，漏判会让挂单在信息事件里被逆向选择。
2. **更快**（0.84s vs 1.20s）。而用户选择了「LLM 失败即暂停挂单」，
   **延迟在这个设计里就是成本**：模型越慢，停摆窗口越长。
3. **分类任务不需要推理**：我们要的是**按规则分类**，
   pro 多出来的推理能力在这里**反而变成噪声源**（它开始论证"相关性"）。

> ⚠️ 这条结论**只对这 7 个边界案例**成立，样本很小，不能外推成"flash 普遍强于 pro"。
> 但它是**用我们的真实判据**测出来的，比通用榜单相关得多。
> 如果以后发现 flash 在某个案例上偏激进（block→none），那一个场景再换 pro。

---

## 3. 与"LLM 失败即暂停挂单"的配合

实测还验证了失败语义（`FAIL_CLOSED_ON_LLM_ERROR=True`）：

| 情形 | 行为 |
|---|---|
| key 无效 / 网络不通 | 重试 `LLM_MAX_RETRY` 次 → 仍失败则 severity 抬到 **block**，理由写明"LLM 不可用，按保守原则暂停挂单" |
| 端点不认 DeepSeek 的 `thinking` 字段（400） | **自动去掉该字段重试一次** → 因此任意 OpenAI 兼容端点都能用（OpenAI / 本地 Ollama / 其它网关） |
| 未配 key | 走确定性日历，输出明写"**本次未使用 LLM**"，且因保守优先**暂停挂单** |
