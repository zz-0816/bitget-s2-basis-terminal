## 1. 工具：让"看着对不对"变成"测出来是不是"

新增三个文件（两棵树都放了）：

| 文件 | 作用 |
|---|---|
| `tools/ui_shot.js` | 零依赖驱动本机 Chrome/Edge（CDP）：真加载、真点击、等条件成立、截整页、收集 console 报错与失败请求 |
| `tools/ui_probe.js` | 页面体检探针：横向溢出 / 字面 markdown / 文字截断 / 元素越界 / 卡住的"加载中…" |
| `tools/ui_check.py` | 把探针结果变成**通过/失败**；没装 Node 或浏览器时**优雅跳过**（评委机器可能没有） |

为什么不引 puppeteer：沙箱装不了依赖，而 Node 22+ 自带 `WebSocket`，直连 CDP 就够，
评委 clone 下来也能跑。

## 2. 项目一：一张表撑破了整页

**现象**：`#assess-table`（执行决策 · 风险与理由）宽 1532px，右缘 2050px，
把文档撑到 2070px（视口 1440）。最右边的「条件」列装的正是
**什么价位、多大仓位、什么时段**——这一列在屏幕上**完全看不到**，必须横向滚动整页。

**根因**（两处叠加）：

1. `th, td { white-space: nowrap }` 是**全表**规则。理由/条件两列装的是**句子**
   （`price_band_bp=4.25；size_usd=5000；timing=仅在 route=in_house 时挂单…`），
   `nowrap` 让它们变成不可断的长条，列宽被顶到 684px + 535px。
2. 该表位于 `.grid2` 的**网格子项**里，而网格子项默认 `min-width: auto` ——
   **不允许收缩到内容宽度以下**，于是整列（连同页面）一起被撑开。

**修法**：`.grid2 > * { min-width: 0 }` 让子项可收缩；对 `#assess-table` 单独
`table-layout: fixed` + 指定列宽 + 长文本列 `white-space: normal` /
`overflow-wrap: anywhere`（长 ASCII token 在中文里没有空格，必须允许任意位置断行）。
数字列照旧 `nowrap`。

## 3. 项目二：三处修正

### 3.1 字面 markdown（4 + 1 处）

页面把**一部分**字段交给 `mdInline()` 渲染、另一部分（标题、表格、证据的
metric/value）走 `esc()` 原样输出。带 `**` 的字符串落进后一类就显示成字面星号。

修的时候是"改掉两个、页面里又冒出另外两个"，所以改成
**先系统扫接口**（`data/…` 所有字符串）再定去向：

| 位置 | 修法 |
|---|---|
| `web/index.html` 两处标题提示 | 改成 `<strong>` |
| `web/index.html` 数据边界标题的反引号 | 改成 `<code>` |
| `web/app.js` "证据强度加权**改变了结论**" | 改成 `<strong>` |
| `agent_team.py` 把 `calendar_quality()` 那行塞进**证据 value** | 证据 value 是**数据**不是排版文本：`.replace("**","")` |

### 3.2 概览首屏 10.3 秒

`/api/overview` 对 10 个标的**串行**各跑一次 `assess()`，约 10.3 秒，且**冷热一个样**。
页面首屏的表因此"加载中…"十秒，点"刷新"再等十秒。

**修法**：按 `(qty, as-of)` 记忆化 + **启动时后台预热**。
缓存在这里是**安全**的：本服务读冻结快照，而决策基准时间现在由数据推导，
同一快照的结论不会变（实时模式可用 `?fresh=1` 强制重算）。
实测 **10.3s → 0.12s**。

### 3.3 离线演示会随时间衰减，且不可复现（最要命的一条）

`analyst_execution_risk()` 默认拿**墙钟 now** 去算"最后一笔成交距今多久"，
而演示读的是**冻结快照**。实测：

| 基准 | `stale_quotes` |
|---|---|
| 墙钟 now（13:53，比快照晚 6.6 h） | **399.3 分钟** ≥ 30 → **触发一票否决** |
| 快照自带时刻（07:16） | **1.7 分钟** → 不触发 |

后果有两个：演示结论**恒为"不参与"**；而且**同一份快照在不同时刻跑出不同结论**
——这与项目自己"可复跑"的主张直接冲突。

**修法**：新增 `time_basis()`，把"现在几点"显式化并**如实标注依据**：

* 数据比墙钟旧超过 `ASOF_AUTO_AGE_MIN`(10 分钟) ⇒ 判为"读冻结快照"，
  按**数据自带时刻**判定（`basis=asof`）；
* 数据新鲜 ⇒ 按墙钟（`basis=wallclock`），实时模式行为不变；
* 显式传 `now_ms` / `?basis=` / `?asof=` 可钉死（测试与复跑需要）。

页面顶部新增绿色的**「决策基准 2026-09-19 07:27:56 UTC（快照时刻）」**，
鼠标悬停给出完整依据。

> ⚠️ 修完 still 有 5 个标的被 `stale_quotes` 否决 —— 查证后那是**真实数据**：
> 现货腿最后一笔成交距今 META 190.5 / SPY 161.0 / TSLA 88.6 / MRVL 44.4 分钟
> （现货腿本身就稀疏，见 `docs/29`）。这是诚实结论，不是时间口径的问题。

### 3.4 修 3.3 时**自己引入并被抓出**的一个 bug

把 `now_ms` 改成 as-of 之后，CLI 的 `--log` 仍然让 `build_log` 回退到墙钟
`generated_ms`。于是**日志记墙钟、决策用快照时刻**，`--replay` 时
"最后一笔成交距今"从 12 分钟变成 6 小时，凭空多出 `agent:stale_quotes`
一票否决 —— 复跑判"不可复现"。

修法：抽出 `log_for_decision()`（CLI 与自检**共用一条口径**，
`now_ms` 一律取 `decision["time_basis"]["now_ms"]`），并在自检里加断言：
**日志记录的 now_ms 必须等于决策用的时刻**。谁把它改回去，自检立刻红。

## 5. 顺带修掉的冷启动等待（项目一）

`/api/data-status` 冷态 6.2 秒、`/api/assess` **4.5 秒**（它要跑事件闸门与成本模型），
而页面前面几块都是秒回 —— 于是首屏只有「执行决策·风险与理由」停在"加载中…"，
看着像卡住。项目一本来就有启动预热线程（覆盖 data-status / overview / timeline /
session-compare），**漏了 assess**。把它补进预热（它本身有 30 秒缓存，预热一次即可）：

| 端点 | 预热前（冷态） | 预热后 |
|---|---|---|
| `/api/assess` | 4.52 s | **0.02 s** |
| `/api/data-status` | 6.21 s | **0.03 s** |
| `/api/overview` | 1.24 s | **0.02 s** |

> 这条也顺带暴露了自检里的一个**竞态**：前端验收原先固定等 9 秒，
> 在冷启动（叠加机器负载）时会偶发超时、误报"卡住的占位符"。
> 已改成**条件等待**（等页面上不再有任何"加载中/读取中"），不再靠猜时间。
