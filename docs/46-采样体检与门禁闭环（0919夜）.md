### 1.2 待观察：`universe` 采样器比设计慢 ~3 倍

| | 设计 | 实测 |
|---|---|---|
| 轮次间隔 | `--interval 30`（`tools/window_watch.py::CYCLE_SEC` 也按 30s 判停摆） | 中位 **78.8 秒**，有效 **87.3 秒** |

原因：它是**轮转式**采样器，每轮要串行请求 24 个配对，走代理每个约 1–1.3 秒 → 单轮就要 30–60 秒。
后果有两个：

1. **全池轮转变慢**：26 轮 × 24 配对 ≈ 3 轮全池 / 38 分钟 → 每个配对约 **12.7 分钟**才刷新一次（设计意图约 4.5 分钟）。
2. ⚠️ **`CYCLE_SEC["universe"]=30` 会让停摆告警误报**：87.3s 已接近 3×30s=90s 的告警线。
3. ⚠️ `coverage_report` 把 universe 的覆盖率算成 **33.9%**（用"轮次×30s/时长"），
   对轮转式采样器**口径不对** —— 它没有丢数据，只是每轮覆盖的配对子集不同。

> 这两条都是**口径/配置**问题，不是数据丢了。要不要动它需要你拍板（会改 `CYCLE_SEC` 与日报口径）。

## 3. Agent 分工 & LLM 使用图

产物：`docs/agent-llm-prompt-map.svg` / `.png`（1440×1010，Chrome 无头渲染）

一句话概括图里那张东西：**5 路 agent 做"发现与论证"，确定性代码做"执行与守边界"，
LLM 只做一件事 —— 判断"是不是信息事件"。**

图里几个**可核对**的点（都从代码里核过，不是画的示意）：

| 图上的说法 | 代码依据 |
|---|---|
| 五路分析师（含 `execution_risk`） | `project2/agent_team.py`：`analyst_basis` / `_sentiment` / `_news` / `_technical` / `_execution_risk` |
| **只有 `news` 这一路碰 LLM** | `analyst_news` → `event_gate.assess()` → `llm_gate()`；其余四路与辩论/交易员/风控**不调 LLM** |
| LLM 与确定性代码的**唯一交界** = 事件闸门 | `severity → 动作` 的映射写在确定性代码里，LLM 不能改 |
| 风控官 **9 条规则** | 实测 `checked_rules = 9`（项目二是 10，多了 agent 规则） |
| 强度权重 实测 1.0 / 已核实 0.85 / 推导 0.6 / 推断 0.3 | `STRENGTH_WEIGHTS` |
| 无可回溯来源时置信度 **封顶 0.40** | `event_gate.CONF_CAP_NO_SOURCE = 0.4` |
| prompt 版本 **v3-2026-09-19** | `common/prompts.py --list` → `event_classify v3-2026-09-19` |
| 防幻觉三层 + 失败关闭 | `_validate_llm_output` / `_with_repair_hint` / `FAIL_CLOSED_ON_LLM_ERROR` |
