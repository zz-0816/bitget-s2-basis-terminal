## 2. 🔴 定性错误：把「窗口内累计」当成「单笔容量」

**证据**（`data/derived/friction_budget.csv` ← `precise_fill_*.csv`）：

| base | 成交笔数 | `notional_sum_usd` | 每笔中位 |
|---|---|---|---|
| AAPL | 30 | **1,558.06** | 19.01 |
| NVDA | 486 | **125,197.41** | 54.50 |

`capturable_notional_usd` 直接等于 `notional_sum_usd`，而它是
`sum(z * s[j][1] for j, z, _, _ in fills)` —— **整个采样窗口内所有成交的累加**。

它**不是**"单笔能吃下多少"。但交易员把它当作**规模上界**之一：

```
规模上界 = min(请求规模, 可捕获名义额(实测), 首档深度 × 占比上限)
```

后果有两个：

1. **误导读者**：页面上"可捕获名义额 = $125,197"与实时盘口的"≤5bp 可吃 = $231"
   （同一时刻、同一标的）相差 **500 倍**，因为两者根本不是同一种量。
2. **规则失效**：`thin_capacity` 的阈值是 `MIN_NOTIONAL_USD × 10 = $1,000`，
   而所有标的的**累计**值都 ≥ $1,405 —— 这条规则**永远不可能触发**，
   看着像保护、实际是装饰。

**修法（只改口径，不改数值方向）**：标签改成
「样本窗口内**累计**可捕获名义额（非单笔容量）」，并在代码注释里写清它只是**宽松上界**
（实际从不 binding）。**没有**把它删掉 —— 它作为"总盘子有多大"的粗上界仍然有效。

> ⚠️ 没有把 `thin_capacity` 的阈值一起改：那会让一条规则突然开始触发，
> 属于**行为变更**，应由你决定。现状已在注释里标明"该规则在累计口径下不具区分度"。

## 3. 🔴 同类缺陷三处：「缺数据」被当成「无约束」

这一类是本次审计**最危险**的发现。风控系统里，"没有数据"必须按**最坏**处理。

### 3.1 `thin_depth`：缺一条腿反而**不触发**（最危险）

旧写法：

```python
"hit": qty > 0 and min(depth_s, depth_p) > 0 and qty > min(depth_s, depth_p) * RATIO
```

那个 `min(...) > 0` 把"某条腿**根本没有盘口**"判成了**不触发** —— 越危险越放行。

**真实触发场景**：`RSOXLUSDT` 的现货盘口在**交易所侧就是空的**。实测证据：

```
现货盘口 RSOXLUSDT      code=00000 success  bids=0 asks=0     ← 空
现货盘口 RNVDAUSDT（对照） code=00000 success  bids=5 asks=5     ← 正常
现货 ticker RSOXLUSDT    code=00000 success                    ← 但有价格（所以基差还能算）
```

**修法**：`hit` 改为**缺盘口 / 首档为 0 一律触发**；`measured` 同时给出**首档与五档**
（项目自己的 `docs/24` §4.3 已实测"只看最优一档会低估 30–280 倍"，
不能只报首档就下结论）。

### 3.2 规模上界：缺一条腿 → 上界为 0，而不是"跳过这条约束"

旧写法 `if l1 > 0: caps.append(...)` —— 于是"没有深度"**反而变成没有约束**，
一个根本下不了单的腿会悄悄放行整笔单。已改为：

```python
else:
    caps.append(("%s/ask **无盘口**（该腿无法成交）—— 按 0 处理" % venue, 0.0))
```

### 3.3 页面侧同类问题（同一晚修完，见 `docs/46`）

- 容量从"全文件最新一轮"改成**每个标的自己的最近齐全轮**（消除半轮读到的空值闪烁）；
- 缺一条腿的标的**不再显示容量数字**，改标「无现货盘口」且**不参与「基差最大」评选**
  （否则 SOXL 的 −265bp 会永远霸榜，把读者往一个做不了的标的上引）。
