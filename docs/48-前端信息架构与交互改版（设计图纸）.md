## 3. 文字分层与折叠规则（这是本次的重点）

### 3.1 三档定义

| 档 | 定义 | 默认态 | 视觉 |
|---|---|---|---|
| **T1 结论** | 一句话结论 + 数字/表格 | **常驻可见** | 正文 14px / 数字 tabular-nums |
| **T2 口径** | "这个数字怎么来的" | **收起**，标题即摘要 | 12px 灰字，`<details>` 折叠行 |
| **T3 方法/局限/免责** | 方法论、已知局限、合规声明 | **收进视图③的折叠组 / 页脚** | 12px 更深灰 |

### 3.2 具体落位（逐条对现有文字，原文一字不改，只改默认可见性）

| 现有文字 | 现位置 | 新档位 |
|---|---|---|
| 主题陈述正文（策略窗口说明） | `.thesis-body` | **T2** → 视图① 一条折叠行 |
| 「基差 = …；基差为负 = 永续更贵…容量才是真正的瓶颈…」 | 双场所表 `p.foot` | **T2**，拆成 2 条折叠行（口径 / 容量） |
| 「倍数 = 休市点差中位 ÷ 盘中点差中位…」 | 分时段表 `p.foot` | **T2** → 视图③ |
| 「上面告诉你哪里有价差；这里告诉你这一单该不该做…」 | 执行决策面板 `p.thesis-line` | **T2** → 视图② |
| 「N 个标的无可回溯事件来源，置信度已压到 0.40」 | `#assess-note` | **T1**（这是结论级信息，必须常驻） |
| 「本项目是做市型价差捕获，不是无风险套利…非投资建议」 | 交易结构 `p.foot.warn` | **T1 → 提到全局页脚常驻**（见 §3.3） |
| `<h2>` 里的 `hint` 小字 | 各面板 | **T2**（折进面板右上角一个「?」按钮的 popover） |

### 3.3 ⚠️ 免责声明**不能**默认折叠（合规）

`p.foot.warn` 那段（"不是无风险套利 / 非投资建议 / 代币 ≠ 股权"）如果收进默认折叠，
在**参赛评审**场景有被判"弱化风险披露"的风险。**建议：提到全局页脚常驻一行**，
其余方法/局限细节才进折叠组。这条请你拍板（§9 第 4 题）。

### 3.4 折叠的交互规格

- **原生 `<details>/<summary>`**：键盘 Enter/Space 天然可用，屏幕阅读器天然播报，不需要自己补 ARIA。
- 高度过渡用 `grid-template-rows: 0fr → 1fr`（**不写死 max-height**，否则长文本会被截断；
  这是 `ui_probe.js` 里 `clipped` 那条红线最容易踩的地方）。
- 每个视图一个「**展开全部 / 收起全部**」开关，状态存 `localStorage`（key 形如 `basis.expand.<view>`）。
- **Esc** 收起当前展开项。
- 表格里的长文本列（`理由 / 警告 / 条件`）见下方 **§3.5 专项**（不是简单"收前 2 条"，而要重构分组）。

## 3.5 专项：执行决策表（**全页最密的一块**）

### 3.5.1 实测（Chrome headless @1440×900，真浏览器探针）

| 指标 | 实测值 |
|---|---|
| 表格总高 | **2394px = 2.7 屏** |
| 平均行高 / 最高行 | **236px / 288px**（SOXL） |
| 每行理由条数 | 平均 **4.1**，最多 **5** |
| 「条件」列 | 每行 **约 81 字符**的 `key=value` 连排 |
| 单元格内容越出行边界 | **0 行**（截图里的"压线"是缩放视觉错觉，**不是 bug** —— 这条同时也钉进探针，见 §7） |

### 3.5.2 三个"看不清"的根因

1. **优先级靠字符表达**：警告是 `!` 前缀、事实是 `·` 前缀 —— 只差一个符号，眼睛无法横扫。
2. **一条理由混了三种信息**：`执行成本：最优方式「双腿全挂单」约 +10.97 bp（含点差/手续费/冲击/逆向选择）`
   = 指标名 + 数值 + 括号口径。挤在一句里，**数字反而不突出**。
3. **结论列被括注撑长**：`不做（成本为正且腿风险高）` —— 括注是解释，不该占主结论的位置。

### 3.5.3 重构：结论行（折叠）+ 理由卡（展开）

**默认态 —— 每行 56px，10 行约 620px（0.7 屏，压缩 74%）**

```
SOXL   [高]  [不做]  只成交一腿 53% 会留裸露敞口          [条件 3]  展开
```

| 列 | 规则 |
|---|---|
| 标的 | 52px 定宽 |
| 风险 | 真徽标（不是有色文字）：高=红底 / 中=黄底 / 低=中性 |
| 结论 | 真徽标：不做 / 谨慎 / 可做；**括注移出**，改成 hover tooltip |
| 一句话主因 | **自动取"最能解释结论的那条"**：有红警告取第一条红，否则取第一条事实；单行 `text-overflow: ellipsis`，`title` 挂全文 |
| 条件 | 收成 `条件 3` 一枚 chip，点开见展开态 |
| 展开 | 行点击 / 键盘 Enter（`aria-expanded` + `aria-controls`） |

**展开态 —— 就地展开约 180px，理由按类型分三组（而不是一串 `·`/`!` 混排）**

| 组 | 来源 | 视觉 |
|---|---|---|
| **红 n · 会改变结论** | 原 `! ` 开头的行 | 红色左边线 + 徽标；左边线是**吸附轨**，扫一眼就知道有几条 |
| **事实 n · 中立背景** | 原 `· ` 开头的行 | 中性、无左边线 |
| **条件** | 原 `key=value` 长串 | 拆成 chips（`价格带 0.81 bp` / `规模 5,000 USD` / `仅在 in_house 挂单`），hover 出解释 |

**每条理由的三段式**：`指标名 +数值+ 一句结论` —— 数值用 `--font-mono` + `tabular-nums` 并加色，
括号里的口径搬进 tooltip。这样"哪个数字导致了什么结论"一眼能对上。

**顶部新增过滤 chips**：`全部 / 仅红 / 仅黄 / 可做` —— 用户最高频的动作是"哪些不能做"，
现在只能自己一行行读。排序沿用现状（风险高在前）。

### 3.5.4 收益

| | 现状 | 提案 | 变化 |
|---|---|---|---|
| 表高 | 2394px（2.7 屏） | 约 620px（0.7 屏） | **−74%** |
| 单行高 | 236 / 288px | 56px | −76% |
| 一眼可见的标的数 | 3~4 个 | **10 个全见** | ×2.5 |

> **一个字都不删**：理由/警告/条件的原文全部保留，只改**默认可见性**与**分组归属**。
> 这点很关键——项目二的自检和 `reproduce_check` 都盯着判据文案，这里不许动语义。

### 3.5.5 新增验收钉子

1. 默认态**每行高 ≤ 64px**（防回退成大行高）。
2. 展开态**单元格内容不得越出行边界**（当前实测 0 行，钉住它）。
3. 展开/收起后**表格总宽不变**（防 `table-layout: fixed` 下抖动）。

## 4. 动效规格（只做四件事，不做无限闪烁）

| # | 场景 | 触发 | 时长 / 缓动 | 实现 | reduced-motion |
|---|---|---|---|---|---|
| 1 | **视图切换** | 点击 tab / hash 变化 | 220ms `cubic-bezier(.16,1,.3,1)` | 新面板 `opacity 0→1` + `translateY(6px)→0` | 直接显示，无过渡 |
| 2 | **数字更新高亮** | 轮询后数值与上次不同 | 600ms 单次闪烁 | 该 `<span>` 背景由 `--accent` 12% 淡回透明 | 仅换一次文字色 |
| 3 | **骨架屏** | 首屏 / 视图首次进入 | 1.4s 循环 shimmer | `background-position` 位移（GPU 友好） | 静态灰块，无循环 |
| 4 | **折叠展开** | `<details>` 开关 | 240ms `ease-out` | `grid-template-rows` + 箭头 `rotate(90deg)` | 瞬时 |

**不做**：无限抖动、焦点抢夺、滚动劫持、超过 3 个属性同时动。
**保留**：右下角红弹窗的**脉冲**（你 2026-09-18 明确要的"闪烁弹窗"，是唯一豁免）。
**颜色**：数字更新的高亮**不用红/绿**——本项目 `--pos/--neg` 是"正/负"语义，拿来表示"变大/变小"会歧义；
统一用中性强调色 `--accent`。

## 6. 无障碍与键盘

- `role=tablist / tab / tabpanel` + `aria-selected` + `aria-controls`；`Home/End/←/→` 切 tab。
- `<details>` 原生语义即可；`<summary>` 必须有可见文案（不靠图标表达状态）。
- `:focus-visible` 保留 `--accent` 2px ring，绝不 `outline:none` 不带替代。
- 对比度：现有暗色令牌实测达标（`--text #e6e9ef` on `--panel #131722` ≈ 13:1），新增颜色沿用令牌，不新造 hex。
- 页首加「跳到主要内容」链接（`#main-content`）。

## 7. 验收红线（**不许破坏现状**）

现有探针 `tools/ui_probe.js` 会检查这 6 条，改版后必须**继续全绿**：

1. 无横向溢出（文档宽 ≤ 视口）
2. 无字面 `**粗体**` / 反引号（改版新增的折叠标题也适用）
3. 无文字被截断（**折叠动画最易踩**，见 §3.4）
4. 无元素越出视口右缘
5. 无卡住的「加载中…」占位符
6. 无 console 报错

**建议同时加固**：给 `tools/ui_check.py` 加一条 ——「**三个视图各切一次**，每次都跑一遍上面 6 条」，
防"某个视图单独溢出"（现在的探针只看默认首屏）。总项数会从 108 增至 111 左右。

**再加 3 条决策表专项探针**（§3.5.5）：

7. 默认态**单元格行高 ≤ 64px**（防回退成 236px 的大行高）
8. 展开态**单元格内容不越出行边界**（当前实测 0 行，钉住）
9. 展开 / 收起后**表格总宽不变**（防 `table-layout: fixed` 下抖动）

### 11.4 实施中发现并修掉的一个**真 bug**（很重要）

**现象**：`web/index.html` 的「口径：基差符号与交易方向」折叠里写着
`基差 = (现货 mid / 永续 mid − 1) × 10000`，并说「基差为负 = 永续更贵 → 多现货 / 空永续」。

**真相**：代码全项目用的是 `(永续/现货 − 1)`，**正 = 永续升水**
（见 `server/app.py` 的 `BASIS_SIGN = +1.0`、`build_panel.py`、`docs/b-side/08`）。
也就是页面写的公式**与代码互为相反数**，并且**符号与方向的对应关系也写反了** ——
照页面读会做反方向。

**为什么一直没被发现**：`tools/verify_basis_convention.py` 只扫 **Python 源码**
（`SRC_FILES` 里全是 `.py`），**页面里写给人看的公式没有任何回归覆盖**。
代码全对、口径回归全绿，页面在骗人。这正是 `docs/08` 那场"甲乙两套约定互为相反数"
争议的残留 —— 源码改了、文档改了，**唯独页面漏了**。

**修法（两层）**：
1. 页面文字改成 `(永续 mid / 现货 mid − 1)`、`基差为正 = 永续更贵 → 多现货 / 空永续`。
2. **补上那层缺失的回归**：`verify_basis_convention.py` 新增第 3 段「页面口径文字扫描」，
   扫 `web/index.html`、`web/app.js`，断言**无旧口径残留**且页面**写明了标准口径**；
   并把它接进 `reproduce_check.py` 的行为检查。
   已做反证：把旧写法塞回去 → 立刻 2 项 FAIL、退出码 1。

### 11.5 又一个坑：`live_cached()` 是异步的

`live_cached()` 的设计是"**立即返回旧值 + 后台线程刷新**"。所以在**刚启动的进程**里
第一次调用它拿到的是 `{}`。对机会名单这很致命 —— 空缓存会被读成
"全部标的都没有实时行情"，而名单的语义是"没有标的达到门槛"，**两者完全不同**。

**修法**：新增 `live_now()` —— 缓存为空时**同步**取一次（实测 20 符号 1.1 秒，
只在冷启动付一次），`build_opportunities()` 开头调它。

### 12.2 「出场证据」→ 这里叫「进场证据」

用户的问题很直接：**"怎么样能够证明我能够进场套利的证据呢？"**

答案就在项目里，只是**从没往接口传过**：`project2/execution_cost.analyse_two_leg()`
一直在算 `p_both`（两腿同时成交）/ `p_part`（只成交一腿）/ `best_cost` / `half_s` / `half_p` /
`leg_risk` / `maker_allowed`，但 `/api/assess` 只回传了"结论"，把**数字丢掉了**。

做法（**纯增量，不改任何判定**）：
1. `server/app.py` 加 `EVIDENCE_KEYS` 白名单 + `_evidence()`，把上述字段摘进 `/api/assess` 每条
   （缺字段就 `None`，**不造数**）。
2. `/api/opportunities` 每条合并 `evidence`，并给出派生量：
   - `net_bp = basis_bp − best_cost`（毛基差减执行成本）
   - `size_fits` / `size_note`：名义额（$5,000）超过"≤5bp 能被吃掉"的量时，**如实说一句** ——
     否则"净 +18 bp"会让人以为能做 $5,000，而盘口其实只吃得下 $1,445。
3. 前端 `oppEvidenceHTML()`：点机会名单的行就地展开，分**三组**（对应小白真正会问的三个问题）——
   **① 能不能挂上 / ② 划不划算 / ③ 最大的坑**。数据全部来自后端，前端只做"数字 + 一句白话"的翻译。

### 12.3 实测证据（2026-09-20 22:05，HOOD，$5,000 名义额）

| 项 | 值 | 白话 |
|---|---|---|
| 基差 | +28.92 bp | 永续比现货贵 |
| ≤5bp 可吃 | 1,445 USD | 这份量能被吃掉，再大就被吃穿 |
| 执行成本 `best_cost` | 10.89 bp | 最优做法是两条腿都挂单 |
| 净（基差 − 成本） | **+18.03 bp** | 空间是正的 |
| **`p_both`** | **0.245%** | **两腿同时成交的概率 —— 极低** |
| **`p_part`** | **12.59%** | **只成交一腿 → 裸露敞口，这才是要防的** |
| `p_none` | 87.17% | 两条腿都没成交 |
| `maker_allowed` | True | 可以挂 maker 单（挂单是赚点差） |

**必须说清的边界**：这套证据能证明的是**"执行层"**——能不能挂上、能吃下多少、
两腿同时成交的概率有多大。它**不能证明能赚钱**：那是回测的事（190 笔 / 65.4 天），
而且项目自己的免责声明写着"这是做市型价差捕获，**不是无风险套利**，散户无法做 mint/redeem"。
