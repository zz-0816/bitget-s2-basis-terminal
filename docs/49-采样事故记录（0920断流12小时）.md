## 4. 根因

**① 直接原因：整棵守护树被一起终止（不是子进程崩溃）。**
`data/logs/supervisor.log` 在 `09-17 02:21:57`（上一次"守护进程启动"）到
`09-20 15:03:26`（本次恢复）之间，**一条"已退出 (exit=...)"都没有**。
而 `sampler_supervisor.ps1` 对任何子进程退出都会写这条日志
（`"{0} 已退出 (exit={1})，{2} 秒后重启"`）。
→ 说明不是某个采样器挂了，而是**守护进程本身（那个 PowerShell 窗口/进程）被整体终止**。

**② 排除机器重启。** `GetTickCount64` 推算系统已连续运行 **216.96 小时**
（开机于 09-11 15:04），事故期间**没有重启**。

**③ 为什么没有自愈（关键的放大因素）：计划任务没注册成功。**
`scripts/install_sampler_guard.ps1` 的设计是：先尝试注册计划任务
（带 `RestartCount 999` / `RestartInterval 1 分钟`，进程崩了自动重启），
**被拒绝（需管理员）才回退到「启动文件夹」**。实测本机：

| 检查项 | 结果 |
|---|---|
| `C:\Windows\System32\Tasks\BitgetS2_SamplerGuard` | **不存在**（计划任务没注册） |
| 启动文件夹 `BitgetS2_SamplerGuard.cmd` | 存在 |

→ 于是只覆盖"**登录时拉起一次**"，**进程被杀后不会重启**。凌晨 02:47 之后没人登录，
就一直空到 15:03 被重新启动。

**④ 恢复时刻 15:03:26 的含义**：`supervisor.log` 记录"守护进程启动" + 四个全新 PID，
锁文件 mtime 全部 `15:03:26` → 这是一次**全新的守护启动**（不是旧进程恢复）。

**⑤ 无法进一步定位的部分（如实说明）**：具体是谁/什么终止了守护（关窗口、任务管理器、
还是睡眠后进程未存活），需要 Windows 事件日志；本机**系统级工具（`wmic`/`schtasks` 等）
被安全策略禁用**，查不到。**已排除本仓库的代码路径**：
`tools/reproduce_check.py`、`tools/ui_check.py`、`server/app.py` 都不会拉起或停止采样守护。
