# 56 · 模拟盘测试方案（路径 B）：完整测下单链路，零真钱

> 起因：用户问「**如果我给了交易权限但是不要进行交易，只是测试功能完整性，可以吗？**」
> 结论：可以，而且**更该用模拟盘**——真实 key 长期保持只读，测试走 Bitget Demo Trading。
>
> 本文是**实施记录 + 操作手册**。实施日期：2026-09-25。

---

## 0. 一句话设计

**把"能不能发单"和"是不是模拟盘"绑死。**

这样两件事同时成立：

- 完整链路**能测到底**（在模拟盘里真下单、真撤单、真读回报）；
- 真实环境**结构上发不出**（不是"约定不发"，是代码走不到）。

---

## 1. 三重闸门（缺一不发）

`common/bitget_private.py::_send_gate()` **按顺序**查，任何一条不过都返回拒绝原因：

| # | 闸门 | 不过会怎样 |
|---|---|---|
| ① | **环境闸门**：`BITGET_PAPTRADING=on`，或有人显式把 `ALLOW_LIVE_TRADING` 改成 `True` | 真实环境即使开了下单开关、显式 `dry_run=False`，也**发不出去** |
| ② | **开关闸门**：`BITGET_TRADE_ENABLED=on` | 默认 off → 直接返回"未启用" |
| ③ | **密钥闸门**：当前环境的密钥必须齐 | 模拟盘开启时只认模拟盘密钥，缺了就报不可用 |

另外还有一条**默认行为**：`place_order()` 的 `dry_run` **默认 True** ——
第一次调用只返回"将要发送的请求"，要真发必须再显式传一次 `dry_run=False`。
两步确认是刻意的：先看清会发生什么，再让它发生。

**参数级拒绝**（在发之前就挡掉）：

- `orderType` 不是 `limit` → 拒绝（市价单会在薄盘口吃穿 5 档，把 3 bp 的问题变成 30 bp）
- 限价单没给 `price` → 拒绝
- 没给 `client_oid`（**幂等键**）→ 拒绝。**不自动生成** —— 自动生成会掩盖"重复提交"，
  而"双击/重试导致下出第二条腿"是这套系统最贵的事故（护栏 #1）

---

## 2. 为什么 `ALLOW_LIVE_TRADING` 要做成具名常量

```python
ALLOW_LIVE_TRADING = False      # common/bitget_private.py
```

要让真实环境能下单，必须**显式改这一行**。这是刻意的：

- 它是一个**可审计、可 grep** 的动作，而不是某个配置项的副作用；
- 它杜绝了"不小心把模拟盘开关指向了真 key"这类事故 ——
  因为模拟盘开启时 `credentials()` **只返回模拟盘密钥**，缺了就报不可用，
  **绝不回落到真实密钥**（实测：模拟盘 on 且未配模拟盘密钥时，
  取到的 key 是空字符串，而不是真实 key）。

## 3. 密钥隔离（实测）

```bash
$ BITGET_PAPTRADING=on python -c "..."     # 模拟盘密钥未配置时
  环境 = paptrading
  可用 = False | 缺 = ['模拟盘 key', '模拟盘 secret', '模拟盘 passphrase']
  credentials 里的 key 前 3 位 = (空)        # ← 没有回落到真实 key
```

真实密钥与模拟盘密钥是 Bitget 上的**两套 key**，本项目把它们放在**两组独立字段**里：

| 环境 | 字段 |
|---|---|
| 真实 | `BITGET_API_KEY` / `_SECRET` / `_PASSPHRASE` |
| 模拟盘 | `BITGET_PAPTRADING_API_KEY` / `_SECRET` / `_PASSPHRASE` |
| 切环境 | `BITGET_PAPTRADING=off`（默认）/ `on` |

## 4. 怎么测（三步）

### 第 1 步：拿一把模拟盘 key（需 KYC）

登录 Bitget → **切换到「模拟盘」** → 个人中心 → API Key 管理 →
**创建「模拟盘 API Key」**（与真实 key 是两套，不能混用）。

### 第 2 步：填进 `.env`

```ini
BITGET_PAPTRADING=on
BITGET_PAPTRADING_API_KEY=...
BITGET_PAPTRADING_API_SECRET=...
BITGET_PAPTRADING_API_PASSPHRASE=...
```

> ⚠️ 开关设为 on 之后，页面会立刻出现一条**常驻横幅**「当前：模拟盘（虚拟资金）」——
> 这是有意的、**不可关闭**：虚拟资金与真实账户必须一直有视觉差异。

### 第 3 步：跑端到端测试

```bash
python tools/demo_trade_test.py                # 完整跑（会真下单、真撤单，都在模拟盘）
python tools/demo_trade_test.py --dry-run-only # 只预览将发的请求，不发单
python tools/demo_trade_test.py --symbol TSLAUSDT --size 1
```

## 5. 测试脚本做了什么（`tools/demo_trade_test.py`）

| 步 | 内容 | 验证了什么 |
|---|---|---|
| 0 | 门禁：不在模拟盘就**直接退出（码 2）**，不做任何事 | 防呆 |
| 1 | 读合约账户资产 + 现货资产 + 持仓 | 补上了此前缺失的**合约保证金读取** |
| 2 | 公开行情取中间价（不需要 key） | 构造挂单价格 |
| 2b | 问交易所要**合约规格**（小数位/最小量）与**账户持仓模式**（双向/单向） | 价量按规格取整；决定要不要带 `tradeSide` |
| 3 | **下单**：限价挂在离市价很远处（默认上浮 50%）→ **不可能成交** | 签名、请求体格式、`clientOid` |
| 4 | 查挂单，确认这一笔在那儿 | **回报解析** |
| 5 | **撤单** | 撤单链路 |
| 6 | 复查挂单里已没有它 | 撤单生效 |
| 7 | 回读持仓，应与开始时一致 | 确认**没成交**（不会留下裸头寸） |
| 8 | 负向：市价单 / 缺幂等键 必须被拒 | 参数级护栏 |

**为什么故意挂在不可能成交的价位**：这样即使脚本跑通，也不会在模拟盘里留下任何头寸，
更不会真的把两条腿做成一条腿。测试的目的只是验证**链路**，不是交易。

## 5.1 首次真下单踩到的三个坑（2026-09-26 实测，根因都是"猜参数"）

第一次真跑**不是一次就通**。三次失败各暴露一个**不能猜**的东西 ——
这三条现在都写进代码并加了自检钉子：

| # | 交易所返回 | 根因 | 修法 |
|---|---|---|---|
| 1 | `code=45115 The price you enter should be a multiple of 0.01` | 价格写成 4 位小数；**每个合约的小数位不同** | `contract_spec()` 问交易所要 `pricePlace`/`priceEndStep`，`round_price()` 按规格取整。**规格取不到就不下单** |
| 2 | `code=40774 The order type for unilateral position must also be the unilateral position type` | **账户持仓模式**是 `hedge_mode`（双向），下单必须带 `tradeSide=open/close`；单向模式则**不能**带 | `pos_mode()` 问账户；双向模式**必须显式给 `trade_side`**（不猜 open/close —— 猜错就是把开仓做成平仓），单向模式不带 |
| 3 | 脚本崩在"查单"（`'str' object has no attribute 'get'`） | `/api/v2/mix/order/orders-pending` 的 `data` **不是列表**，而是 `{entrustedList:[...], endId:"..."}` | `read_pending_orders()` 兼容两种形状，且**宁可返回空列表也不抛异常** |

**坑 3 带出一个更重要的教训**：那一步崩掉时，**单已经挂在交易所上了**（脚本没走到撤单，只能手工撤）。
所以现在测试脚本把第 4~7 步整个包在 `try/finally` 里 ——
**只要单发出去过，无论后面哪一步怎么异常，收尾都会强制撤单**。
一个碰真单的脚本，"撤单"必须是 finally 级别的保证，不能靠"顺利走到底"。

### 首次成功跑通的实测结果

```
【3】真发：交易所受理（code=00000 msg=success）  orderId = 1487635010449145857
【4】在挂单里找到了这一笔：{"symbol":"TSLAUSDT","side":"sell","posSide":"short",
      "price":"558.46","size":"1","status":"live","clientOid":"demo-..."}
【5】撤单成功（msg=success）
【6】该笔已从挂单中消失
```

⇒ 测试在交易所侧**没有留下任何东西**。

## 6. 补腿功能：docs/54 §2 那 7 道护栏的落地（2026-09-26）

**原则一句话：宁可裸露，也不硬吃。** 任何一道护栏不过，就拒绝下单并说清卡在哪一条 ——
裸露敞口是已知的、有风控提醒覆盖的风险；价格失控 / 方向做反是**未知损失**。

| 文件 | 作用 |
|---|---|
| `common/repair.py` | **补腿计划器 + 执行器**：`build_plan()` 只读产出计划（含 7 道护栏逐条结论），`execute()` 默认 dry-run、`confirm=True` 才发 |
| `tools/repair_leg.py` | CLI：`--base TSLA` 出计划 / `--all` 扫全部单腿标的 / `--confirm` 真发 |
| `tools/repair_lifecycle_test.py` | 完整测试（见 §6.3） |

### 6.1 七道护栏的具体落点

| # | 护栏 | 在代码里怎么落 |
|---|---|---|
| 1 | 幂等键 + 重读持仓 | `client_oid` 由计划确定性生成（同计划重复执行 = 同一个键） |
| 2 | 补错方向 | 缺哪条腿**由 `pair_legs()` 读真实持仓推出**，不接收调用方传入的持仓；`execute()` 前**再读一次**确认状态没变 |
| 3 | 补错数量 | **由已成交腿的数量反推**（`spot_qty` / `perp_size`，1:1），再按规格取整 —— 不用页面上的"建议规模" |
| 4 | 不该补时补 | `state` 必须在 `bitget_private.NAKED_STATES`（= `spot_only` / `perp_only`）内；`both` / `flat` 一律拒绝 |
| 5 | 超余额 | 现货腿查**现货账户 USDT**、永续腿查**合约账户可用保证金**（`crossedMaxAvailable` ÷ 杠杆），留 2% 余量 |
| 6 | 价格失控 | **只发限价单**；限价 = 对手价，且 `|限价/中间价−1|×10000 ≤ MAX_SLIP_BP=5`，超限拒绝 |
| 7 | 密钥泄漏 | 密钥只在 `.env`（`.gitignore` 覆盖）；计划里只输出可用性，不打印密钥 |

另加**两条工程约束**：`PLAN_TTL_SEC=60`（**不拿旧状态下单**：过期计划拒绝执行）；
`execute()` 默认 dry-run（要 `confirm=True` 才发）。

### 6.2 ⚠️ 一个必须说清的环境限制：**模拟盘不提供 rToken 现货**

实测（2026-09-26）：模拟盘里下 `RTSLAUSDT` 返回
`code=40034 Parameter RTSLAUSDT does not exist`；而**普通现货是支持的**
（`BTCUSDT` 的订单进到了价格带校验 `41118`，说明链路通）。

所以测试策略是"**能真跑的真跑、跑不了的如实标注**"：

| 分支 | 怎么测 | 结果 |
|---|---|---|
| 现货下单链路（签名/字段/撤单） | 用 `BTCUSDT` 真挂一笔**挂着不成交**的买单 → 撤单 | ✅ 真的通了 |
| **补永续腿** | 用**合成现货持仓**造出 `spot_only` 状态 → 计划 → **真发到模拟盘** → 查单 → 撤单 | ✅ 真的通了（含 7 道护栏全过） |
| 补现货腿（买 rToken） | 合成 `perp_only` 状态 → 计划（护栏逐条算）→ 只做 dry-run | ⚠️ 真发受环境限制，**如实标注、不算通过** |
| flat / both / 过期计划 | 应被护栏拦下 | ✅ 三种拒绝都验证了 |

### 6.3 实测结果（`tools/repair_lifecycle_test.py`）

```
【1】现货下单链路（BTCUSDT）受理 → 撤单成功
【2】[ ~ ] 模拟盘不提供 rToken 现货（code=40034）—— 如实标注，不算通过
【3】flat -> 护栏 #4/#2 拦下
【4】合成 spot_only -> 7 道护栏全过 -> 补永续腿**真发受理** -> 查单找到 -> 撤单成功
       护栏 #6 实测滑点 0.13 bp ≤ 5 bp；护栏 #5 需要 379.74 ≤ 可用 9997.21
【5】合成 perp_only -> 计划为补现货腿；护栏 #5 反而拦下了（合成现货余额 0）
【6】both -> 护栏 #4 拦下
【7】过期计划 -> 拒绝执行
【8】独立复核：合约挂单 0 笔 / 持仓 0 条
结论：19 项全部通过 / 1 项受环境限制跳过
```

### 6.4 本轮被测试逼出来的三个真 bug（都已修 + 加钉子）

| bug | 表现 | 修法 |
|---|---|---|
| **状态名写错** | 我在 `repair.py` / `repair_leg.py` 里写成 `only_spot`/`only_perp`，而真实值是 **`spot_only`/`perp_only`** → 永远匹配不上，明明缺腿却报"无腿可补" | 改为复用 `bitget_private.NAKED_STATES` 常量（**不在两处各写一份**） |
| **撤单不分现货/合约** | 用合约撤单端点去撤现货单，撤不掉（测试第 1 步失败） | `cancel_order(..., kind=)`；默认 `auto` 先试合约再试现货，并回报用了哪个端点 |
| **配对口径又写了一遍** | `s == base` 永远匹配不上（配对着里是 `RTSLAUSDT`） | 复用 `repair._plan_pair()`，口径与 `pair_legs()` 一致 |

> 三条的**共同根因**：**同一件事在两处各写一份**。本项目已因这个问题反复踩坑
> （基差口径、盘口深度、回测笔数、状态名…）—— 凡是"别处也在算同一个东西"，
> 就必须复用同一份，并加自检钉子。

## 6. 自检钉住了什么（`tools/reproduce_check.py`）

| 断言 | 类型 |
|---|---|
| 真实环境 + 开关打开 + 显式 `dry_run=False` → **仍发不出去** | **行为级**（真跑一次看返回） |
| 模拟盘里默认 `dry_run` → 只列不发的请求，且标明 `env=paptrading` | **行为级** |
| `paptrading_enabled()` / `h["paptrading"]="1"` / `ALLOW_LIVE_TRADING = False` | 源码级 |
| 后端暴露 `trade_env`、前端有 `#envbar` 横幅容器 | 源码级 |

`common/bitget_private.py --selftest` 另有 9 条纯函数断言（不需要联网、不需要 key），
把三重闸门逐条钉住。

## 7. 边界（必须说清，仍然不为真钱做任何事）

- **订单只可能落在模拟盘**。真实账户即使有交易权限，本项目也**没有**任何发送路径
  （`ALLOW_LIVE_TRADING = False`）。
- 想真的允许真实交易，必须**显式改那一行常量** —— 这是刻意的门槛，不是遗漏。
- 截至目前，**7 道护栏里只有部分落地**（幂等键强制、限价强制、环境强制）；
  撤单/回报解析已通。**"补腿"仍不提供**：`recommend_action()` 只给建议，
  没有把建议变成订单的入口。真要做真实交易，仍按 `docs/54` §2 把 7 道护栏逐条落地。
