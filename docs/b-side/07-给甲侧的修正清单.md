## 二、要改的 5 处（按优先级）

### 1️⃣ 基差符号：**两套约定必须统一**（必改，会改数字）

- **现状**：你全量用 `(现货/永续 − 1)`（`build_panel.py:176`，与你 `00` §5.2 定义一致、全文自洽）→ 快照 TSLA = **−27.20**；乙侧用标准期货口径 `(永续/现货 − 1)` → **+27.27**。
- **复算确认**：1h 面板按你口径 **0 行不符**、按乙侧口径 13,586 行不符；1day 面板 0 / 22,679 → **你的口径没错，是两套约定**，换算＝**互为相反数**。
- **风险**：同一句「基差 −20bp」在两边读出的方向相反 → 直接决定「多现货/空永续」还是反过来（你自己登记的 K10）。
- **改法**：统一为 **`(永续/现货 − 1)`，正 = 永续升水**（与「basis = 期货 − 现货」一致）；代码里加常量 `BASIS_SIGN = +1`；`00/03/04/06` 里所有基差数字**翻号**并留一句「本轮已统一口径」。

### 2️⃣ 面板 `--max-gap 3` 在**日线**上 = 允许"拿 3 天前的现货价配今天的永续价"（必改，会改数字）

- **证据**：1day 面板 **3,026 / 22,948 行（13.2%）** 的 `spot_lag_bars>0`。
  - 滞后=0：sd **91.65**、\|bp\|>200 占 **1.36%**
  - 滞后>0：sd **162.21**、\|bp\|>200 占 **11.63%**
  - **\|bp\|>300 的 341 行里，52.5% 出自滞后>0**（全样本仅 13.2%）
- **原因**：现货零成交日不上线；一旦落到前 1–3 天的收盘价，"基差"里就混进标的**多日涨跌幅**（±100~300bp），而真信号只有 ~10bp；**半衰期只有 6 分钟，任何跨 bar 拼接都毁信号**。
- **改法**：`--max-gap 0`（至少日线必须 0；1h 用 1），`lag>0` 一律记缺测，重跑两张面板。
- ⚠️ **副作用必须同步**：剔除滞后>0 后，1day 的「休市 − 盘中」差从 **3.4bp 缩到 1.0bp**（−8.13 vs −7.08）→ **"休市时段基差更负"方向仍成立、幅度要下调**。
  （好消息：**1h 面板结论稳健**，剔除后四时段中位几乎不动 → 报告的主力证据仍可用。）

### 3️⃣ 日线面板的 `closed` 标签 ≠ 休市，而是"周六/周日那一根"（改表述）

- **证据**：日线面板 23,330 行的 `ts` **全部是 `16:00Z`**（= 北京次日 00:00，Bitget 日线按 UTC+8 切，一根覆盖整天）；`closed` 行 **100% 是周六（3,148）+ 周日（3,157）**。
- **含义**：`session_of()` 按 bar 开盘时刻打标签 → 工作日夜间休市被并进 `intraday`；「休市 vs 盘中」实为「**周末 bar vs 工作日 bar**」。
- **改法**：时段结论**只用 1h 面板**；日线面板列名改 `weekend/weekday` 或在表下注明"日线粒度无法区分盘中/夜间"。

### 4️⃣ 标的池里混着非股票，且极端值高度集中在 `CLUSDT`（改口径/分层）

- 213 个可用配对里有 **3 个商品**：`RCLUSDT`（原油）、`RBZUSDT`（布伦特）、`RZSUSDT`（大豆）→ 别写"213 支代币化美股"，写"213 个 RWA 配对"。
- **`CLUSDT` 一个标的占了 \|基差\|>300bp 的 341 行里的 128 行**，且已被你的质量闸门标 `suspect`（共 5 个：`CL/MSTU/MU/SKHY/SOXS`）。
- **改法**：统计池分「股票 / 其他」两层；suspect 默认排除并写明剔除理由。

### 5️⃣ F5 闸门必须用**可成交价**，不能用 mid（策略生死）

同一时点三种"基差"（标准口径，正 = 永续溢价），用你 171 轮盘口重算：

| 口径 | 全体中位 | 扣费后（现货taker10 + 永续taker6 = 16bp） |
|---|---|---|
| `B_mid`（中间价对中间价，= 你面板的算法） | **+15.6 bp** | **−0.4 bp（死）** |
| `B_taker`（两腿都吃单） | +12.1 bp | −3.5 bp |
| `B_maker`（**现货腿挂 bid 成交** + 永续吃单） | **+20.5 bp** | **+4.5 bp** |

- **结论**：`B_maker − B_mid ≈ 半个现货点差` → **收益的一大块就是"现货腿不付点差"**；现货腿一旦吃单，中位基差被手续费吃光。
- **点差最宽的标的反而最差**：`MRVL` 现货点差 45.63bp（全池最宽）但中位基差只 +8.45bp → **吃单后倒亏 15bp**；好标的是 `GOOGL/META/NVDA`（点差 8–14bp、基差 22–24bp）。
- **改法**：闸门改为「**逐标的的 `B_maker`/`B_taker` − 实际费率 > 安全边际**」，并把三列一起写进面板；**OQ-1（现货费率，含是否在 0 费活动内）是唯一的分水岭，请优先查实并截图**。

## 三、顺手发现（非阻塞，但会误导后续使用者）

1. `pair_quality` 的**注释与实现不一致**：注释写"超过 10% 的行**触发合理性闸门**"，实现统计的是**所有空基差行**（无现货 + 现货过旧 + 闸门剔除，三者混算）→ 语义不同，建议改注释或拆成两列。另 `suspect_pairs` 变量算完未被使用（死代码）。
2. **采样文件不止一个写入者**：`data/spread/2026-09-12.csv` 80.5 分钟 **171 轮**（60 秒节奏应约 81 轮 = **2.1 倍**），轮间隔成 **16.5 + 43.6 ≈ 60 的互补对**，并出现 **3.4 秒**间隔 → 两个 60 秒循环（或重启叠加）。
   ⚠️ 你的自检键是 `(ts_ms, symbol, venue)` 完全相等 —— **两个进程各打自己的毫秒戳，必然测不出重复**，所以"0 重复"是**假阴性**。
   正确检测：**每分钟轮数 ≈ 1** / 间隔是否成互补对 / 每轮行数是否恰等于配对数×2。
3. 顶档深度口径：你写"永续顶部深度中位约 $400"，我按 `universe.csv` 的 `perp_bid_depth_usd` 算是 **中位 $158**（min $2 / max $298k，**< $1000 的有 127/213**）→ 方向一致，**注明口径**（顶档 vs min(bid,ask)、单点快照 vs 分位）即可。
4. **`base` 字段有派生 bug**（09-13 追加）：`spread_sampler.py:236` 写的是 `symbol.rstrip("USDT").lstrip("R")` ——
   `rstrip` 的参数是**字符集**不是后缀，凡以 `T/S/D/U` 结尾的代码都会被多剥一位：
   `HOODUSDT → HOO`（本次采样 CSV 实测）、`MSFTUSDT → MSF`。`universe.csv` 不受影响（另一套逻辑）。
   功能上不影响分组，但**按 `base` 与原生股代码 join 会静默失配**。改法：`sym[:-4] if sym.endswith("USDT") else sym`。
5. **锁检测在 Windows 上会把启动打崩**（09-13 追加）：锁文件残留时，`_pid_alive()` 里的
   `os.kill(pid, 0)` 对**已经消失的 pid** 抛 `OSError: [WinError 87] 参数错误`，
   于是**下一次启动被 traceback 挡死，只能手动删锁**（乙侧已实际踩到）。
   改法：`except Exception: return False`，并把锁分支整体包 `try`，**锁检测失败按无主锁接管**；
   更彻底的是用**独占文件句柄**代替 pid 探测（进程死掉 OS 自动释放句柄）。
