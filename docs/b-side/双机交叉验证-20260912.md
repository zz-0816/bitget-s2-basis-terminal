# 双机交叉验证：两台机器同时段同标的的盘口一致性

> **结论先行**：两份采样**可以安全合并**——同一标的、同一分钟、同一场所的中间价，中位差 **0.00 bp**、均值 **0.20 bp**；
> 差异集中在流动性最差的**永续腿**，最大 **5.92 bp**（MRVL），远小于被测量的基差（+8 ~ +12 bp）与点差（3 ~ 46 bp）。
> 复现：`python tools/b_side_crosscheck.py`
> 时点：2026-09-13 00:45 CST

---

## 一、为什么会有这次对照

两个采样实例在**两台不同机器**上独立运行（你那边 core + universe，乙侧本机一份），采集同一批标的的逐分钟盘口。
Bitget **不提供历史 bid/ask**，所以这批数据不可回补；在合并之前必须先回答一个问题：

> **两台机器采的是不是同一件事？** 若存在口径差异（时间戳定义、venue 判定、mid vs 可成交价），
> 合并后会引入无法察觉的系统偏差。

---

## 二、方法

| 步骤 | 做法 |
|---|---|
| 对齐键 | `(分钟桶, base, venue)`，分钟桶 = `ts_ms // 60000` |
| 比较量 | 中间价 `mid = (bid + ask) / 2`，相对差 `Δ = (mid_乙 / mid_甲 − 1) × 10⁴`（bp） |
| 另比 | 点差 `Δspread = spread_bp_乙 − spread_bp_甲`（bp） |
| 样本 | 甲侧 `data/spread/2026-09-12.csv`（13:01–15:52Z，364 轮） ↔ 乙侧 `data/b-side/spread/2026-09-12.csv`（15:14–15:39Z，26 轮） |
| 重叠 | **26 分钟、492 个 `(分钟, 标的, 场所)` 三元组** |

## 四、四条解读

**① 现货腿逐字相同，差异只在永续腿。**
样本里现货腿大量出现"两侧 bid/ask 一模一样"，而永续腿常有几 bp 差异。
这与 `09` 的市场结构结论一致：**现货在平台所内撮合（同一订单簿），永续是独立市场**——
两台机器看到同一个现货盘口，但永续报价在秒级抖动。

**② 差异与流动性负相关。**
最大差 5.92 bp 落在 `MRVL` —— 恰好是全池**点差最宽**（45.63 bp）的标的；`SPY`/`HOOD` 这种流动性好的只有 0.4 bp 量级。

**③ 单点快照噪声 ≈ 0.2 bp，对被测量可忽略。**
基差本身是 8–12 bp、点差是 3–46 bp，而测量噪声中位为 0、均值 0.2 bp ——
**对 `B_mid` 类研究、分时段中位数统计没有实质影响**。
但要注意：这不是"数据无误差"，而是"两台机器读同一时刻的盘口几乎无差"；**真实风险是挂单能否成交（见 `docs/11` 的现货冻结发现），不是报价精度**。

**④ 合并仍须保留来源标记。**
两份数据的字段、时间戳定义、venue 判定**完全一致**（列名逐字相同），可直接 `csv` 拼接；
但**不同机器的轮次密度不同**（甲侧 13:01 起持续采、乙侧 15:14 起），
直接合并会让 15:14–15:39 这段的轮次密度翻倍 —— **时间加权统计前须按轮次去重**，
与你 `08` §三.A 里对"两个实例并行"时段的处理原则相同。
