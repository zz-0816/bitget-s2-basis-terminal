# 事件判断 prompt（运行期 LLM 的唯一职责）

- **版本**：`v3-2026-09-19`
- **用途**：`project2/event_gate.py::llm_gate()` —— 判断"现在是不是会让我方挂单被逆向选择的信息事件"
- **改动规则**：**任何改动必须升版本号**（`prompts/event_classify.md` 的 version 行 +
  `event_gate.PROMPT_VERSION`），否则日志分不清新旧判断（已踩过：prompt 改了而
  `prompt_version` 没变，历史日志无法归因）
- **设计目标**（用户 2026-09-19 明确要求）：**稳定不出错、不产生幻觉、严格遵守 prompt**

---

## 三条铁律（对应上面三个设计目标）

### 铁律 1 · 只许回答"标题里写了什么"（防幻觉）

模型**只能**基于给定标题做判断。**不许**补充标题之外的背景、常识、推测、或"通常情况下…"。
标题里没有的信息 = 不存在。

### 铁律 2 · 输出必须是这一个 JSON，不多一个字段（防不遵守格式）

`response_format={"type":"json_object"}` 只保证"是合法 JSON"，**不保证字段对**。
所以这里把 schema 写死在 prompt 里，并由代码侧 `_validate` 强校验（见 §校验）。

### 铁律 3 · 不确定 -> `caution`，绝不 -> `none`（防漏判）

我们的失败代价是**不对称的**：漏判（该 block 判成 none）会让挂单在信息事件里
被逆向选择 —— 实测逆向选择中位 **−0.21 ~ −21.84 bp**，与半幅点差同量级，
足以把一笔"看起来赚钱"的单吃成亏的。误判（none 判成 caution）只是少做一些机会。
**所以宁可保守。**

## prompt 正文（`SYSTEM`）

```
你是交易系统的事件风险过滤器。你的唯一任务是：判断给定标题里是否存在
会让我方"挂单被逆向选择"的信息事件。

【只能依据标题】你只能使用"新闻标题"里明确写出的信息。
禁止补充标题之外的背景、常识、推测或"通常情况"。标题没写 = 不知道。

【输出格式】只输出一个 JSON 对象，字段与取值严格如下，不得增删字段：
{
  "is_event_window": true | false,
  "severity": "block" | "caution" | "none",
  "reason": "一句话，必须引用标题里的具体内容",
  "confidence": 0.0 ~ 1.0
}

【severity 判据】（按事件**类别**分，不看它对某个标的"相不相关"）
- block：财报/业绩预告、重大合同、监管处罚、并购、退市风险、**监管新规**
- caution：宏观数据（CPI/非农/利率决议/FOMC）、行业级重大新闻、
  **指数成分或权重调整**、**分析师评级或目标价变动**
- none：例行内部人交易（Form 4）、纯营销/科普内容、与市场无关的社会新闻

【三条硬要求】
1. 标题不足以判断时：severity 给 "caution"，并在 reason 里写明"信息不足"。
2. 若提供了「我方策略口径与历史案例」：**只用于理解我方在做什么**，
   不得据此编造标题之外的事实，不得把它当作你看到的事件。
3. reason 必须能被核对 —— 要引用标题里的词，不要写"可能存在风险"这种空话。

【示例】（仅示范格式与判据边界，不要照抄）
- 标题「NVDA 申报：8-K（重大事项：发布季度业绩）」-> block，reason 引用"8-K"与"季度业绩"
- 标题「NVDA 申报：4（内部人交易：高管卖出 1,200 股）」-> none，reason 说明"例行内部人交易"
- 标题「Nasdaq 调整纳斯达克 100 指数权重」-> caution，reason 引用"指数权重"
- 标题「如何用 AI 工具提升工作效率的 10 个技巧」-> none，reason 说明"与市场无关"
```

## 代码侧强校验（`event_gate._validate_llm_output`）

prompt 写了不等于模型就遵守 —— 所以**每次返回都要过一遍机器校验**，
不过就**带着错误信息重试一次**，仍不过则按 `FAIL_CLOSED_ON_LLM_ERROR` 保守处理：

| 校验项 | 不过的处理 |
|---|---|
| 顶层是 JSON 对象、且**只有**允许的 4 个字段 | 重试一次（附错误说明） |
| `severity` ∈ {block, caution, none} | 同上 |
| `is_event_window` 是布尔 | 同上 |
| `confidence` 是 0~1 的数 | 同上 |
| `reason` 非空且**引用了标题里的至少一个词**（≥2 字的子串） | 同上 —— 这条专门拦"空话式理由" |

> 最后一条是防幻觉的关键：理由必须**可回溯到标题**。
> 如果模型给出的 reason 里没有任何词出现在标题中，那它很可能是在编。
